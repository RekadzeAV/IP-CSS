## 🔍 Детали реализации

### Логирование в AuthorizationMiddleware

**Типы событий:**
- `UNAUTHORIZED_ACCESS` - попытка доступа без аутентификации
- `PERMISSION_DENIED` - отказ в доступе из-за недостаточных прав

**Информация в логах:**
- User ID и username (если доступны)
- IP адрес запроса
- Ресурс (путь запроса)
- Требуемое разрешение или роль

### Логирование изменений прав доступа

**Событие:** `CONFIGURATION_CHANGE` с типом `role_change`

**Детали:**
- `action`: "role_change"
- `target_user_id`: ID пользователя, чья роль изменилась
- `target_username`: Username пользователя
- `old_role`: Старая роль
- `new_role`: Новая роль

### Логирование изменений конфигурации

**Событие:** `CONFIGURATION_CHANGE` с типом `settings_update`

**Детали:**
- `action`: "settings_update"
- `updated_count`: Количество измененных настроек
- `settings_keys`: Список ключей измененных настроек

## 📝 Примеры логов

### Несанкционированный доступ:
```
[UNAUTHORIZED_ACCESS] IP: 192.168.1.100 Details: resource=/api/v1/cameras
```

### Отказ в доступе:
```
[PERMISSION_DENIED] User: admin (ID: user-123) IP: 192.168.1.100 Details: resource=/api/v1/users, required_permission=role:ADMIN
```

### Изменение роли:
```
[CONFIGURATION_CHANGE] User: admin (ID: admin-456) IP: 192.168.1.100 Details: action=role_change, target_user_id=user-123, target_username=operator, old_role=VIEWER, new_role=OPERATOR
```

### Изменение настроек:
```
[CONFIGURATION_CHANGE] User: admin (ID: admin-456) IP: 192.168.1.100 Details: action=settings_update, updated_count=3, settings_keys=[max_recording_duration, storage_path, retention_days]
```
