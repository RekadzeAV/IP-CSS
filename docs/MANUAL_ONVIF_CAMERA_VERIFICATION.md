# Проверка с реальной ONVIF-камерой (задача 1.4.3)

**Цель:** Провести проверку подписки на события ONVIF с одной реальной камерой: PullPoint, типы событий, задержки. Основной путь — автоматизированный.

**Связано:** [MVP_PHASED_IMPLEMENTATION_PLAN.md](../archive/docs-deprecated-2026-09-04/MVP_PHASED_IMPLEMENTATION_PLAN.md) — этап 1.4, задача 1.4.3.

**Автоматизированные сценарии (API):**
- базовый: `scripts/onvif-events-api-verification.ps1`
- устойчивость (restart/re-subscribe): `scripts/onvif-events-resilience-verification.ps1`

См. [automation/MVP_PHASE1_AUTOMATED_ACCEPTANCE.md](automation/MVP_PHASE1_AUTOMATED_ACCEPTANCE.md).
Без реальной камеры приёмка по P1-2 опирается на юнит/интеграционные тесты `OnvifEvent*` в репозитории.

---

## Требования

- Одна реальная ONVIF-камера в той же сети, что и машина с сервером API (или доступная по IP).
- Учётные данные камеры (логин/пароль).
- Сервер API запущен с включёнными ONVIF Events.
- Веб-клиент для проверки списка событий и WebSocket (опционально — Desktop/Android).

---

## Подготовка

### 1. Конфигурация сервера API

Убедитесь, что ONVIF Events включён. В `.env` или в окружении сервера:

```bash
# Минимум для проверки (остальное — по умолчанию)
ONVIF_EVENTS_ENABLED=true
```

Полный пример переменных — `config/onvif-events.example.env`. По умолчанию:
- `ONVIF_PULL_INTERVAL_MS=5000` (опрос PullPoint каждые 5 с)
- `ONVIF_PULL_TIMEOUT_MS=500`
- `ONVIF_USE_PULL_POINT=true`

### 2. Данные камеры

Подготовьте:
- **URL камеры** — например `http://192.168.1.100` или `http://192.168.1.100:8080` (должен начинаться с `http://` или `https://`).
- **Логин и пароль** для ONVIF (часто те же, что для веб-интерфейса).

Можно использовать локальный конфиг тестовых камер: `config/test-cameras.local.json` (см. `config/README-TEST-CAMERAS.md`) — оттуда взять `host`, порт (часто 80 или 8080) и собрать URL.

### 3. Проверка с камерами из локальной сети (`config/test-cameras.local.json`)

Если у вас уже есть `config/test-cameras.local.json` с камерами в локальной сети (например, 192.168.10.20–24), можно использовать их для проверки ONVIF:

- **URL камеры для ONVIF:** `http://<host>` (порт 80) или `http://<host>:8080` — в конфиге указаны `host`, в `defaults.httpPorts` — типичные порты 80, 8080, 443.
- **Учётные данные:** из полей `username` и `password` каждой камеры в JSON.

**Пример для первой камеры из конфига** (host `192.168.10.20`, логин `survival`, пароль из конфига):

- URL: `http://192.168.10.20` (если ONVIF на порту 80) или `http://192.168.10.20:8080`.
- Добавление камеры через API: тело запроса `POST /api/v1/cameras`:  
  `{ "name": "Test ONVIF 20", "url": "http://192.168.10.20", "username": "survival", "password": "<пароль из test-cameras.local.json>" }`.

**Скрипт для пошаговой проверки через API:**  
Запустите сервер API с `ONVIF_EVENTS_ENABLED=true`, затем выполните:

```powershell
.\scripts\onvif-manual-verification.ps1 -ApiBase "http://localhost:8080" -AdminUser "admin" -AdminPassword "<пароль админа>"
```

Скрипт выполняет: вход в API, добавление первой камеры из `config/test-cameras.local.json`, ожидание ~15 с, запрос `GET /api/v1/events`. Дальше вручную: инициируйте событие на камере (движение и т.п.), снова запросите события или откройте веб-интерфейс `/events`.

## Шаги проверки

> Ниже — reference-checklist. Для фактической приёмки используйте автоматизированные скрипты и прикладывайте их артефакты (`diagnostics/onvif-events/*.json`, `*summary.md`).

### Шаг 1. Запуск сервера API

1. Запустите сервер API с включённым ONVIF Events.
2. В логах при старте должно появиться сообщение вида:
   - `ONVIF: subscribed to X of Y cameras at startup` (если камеры уже есть в БД) или просто отсутствие ошибок подписки.

Если камер в БД ещё нет — это нормально; подписка создастся при добавлении камеры (шаг 2).

### Шаг 2. Добавление камеры

1. Через веб-интерфейс или API добавьте камеру с вашим URL и учётными данными.
   - Пример: `POST /api/v1/cameras` с телом `{ "name": "Test ONVIF", "url": "http://192.168.1.100", "username": "admin", "password": "***" }`.
2. Проверьте логи сервера: не должно быть ошибок подписки для этой камеры (при ошибке будет `Failed to subscribe to ONVIF events for camera: ...`).

**Ожидание:** Камера создана, сервер в фоне подписался на её события (PullPoint).

### Шаг 3. Проверка PullPoint и прихода событий

1. **Инициируйте событие на камере** (если камера поддерживает):
   - Движение перед камерой (MotionAlarm),
   - или срабатывание входа/выхода (IO),
   - или, если есть, тест «Tamper» и т.п.
2. Подождите не более **2× ONVIF_PULL_INTERVAL_MS** (по умолчанию до ~10 с).
3. Проверьте:
   - **Веб:** страница `/events` — новое событие появилось в списке (при подписке на WebSocket — в реальном времени).
   - **API:** `GET /api/v1/events` — в ответе есть событие с `cameraId` вашей камеры.

**Ожидание:** Событие от камеры появилось в системе и в UI/API.

### Шаг 4. Типы событий

По возможности проверьте несколько типов (если камера их отдаёт):

| Что проверить | ONVIF-топик (пример) | Ожидаемый EventType / Severity |
|---------------|----------------------|---------------------------------|
| Движение      | MotionAlarm           | MOTION_DETECTION / INFO         |
| Вторжение     | IntrusionDetector    | OBJECT_DETECTION / CRITICAL     |
| Вандализм     | TamperDetected       | OTHER / CRITICAL                |
| Потеря видео  | VideoSourceLost      | CAMERA_OFFLINE / WARNING        |

Маппинг описан в [ONVIF_EVENT_INTEGRATION.md](ONVIF_EVENT_INTEGRATION.md) (раздел «Маппинг ONVIF событий»).

**Ожидание:** Тип и критичность в UI/API соответствуют ожидаемым (или логично маппятся в имеющиеся типы).

### Шаг 5. Задержки

1. Зафиксируйте время срабатывания на камере (например, по времени движения или по логу камеры).
2. Зафиксируйте время появления события в UI или в `GET /api/v1/events`.
3. Оцените задержку: она не должна превышать примерно **ONVIF_PULL_INTERVAL_MS + ONVIF_PULL_TIMEOUT_MS** (по умолчанию ~5,5 с) плюс сетевая задержка.

**Ожидание:** Задержка приемлема (типично до 10–15 с при интервале 5 с).

### Шаг 6. Удаление камеры и отписка

1. Удалите камеру через API или веб (`DELETE /api/v1/cameras/{id}`).
2. В логах не должно быть падений; при корректной отписке — предупреждений об ошибке Unsubscribe не будет.

**Ожидание:** После удаления камеры подписка снята, новых событий от этой камеры не приходит.

### Шаг 7. Перезапуск сервера (восстановление подписок)

1. Снова добавьте камеру (или оставьте одну в БД).
2. Перезапустите сервер API.
3. В логах при старте: `ONVIF: subscribed to 1 of 1 cameras at startup` (или аналог).
4. Снова инициируйте событие на камере и убедитесь, что оно появляется в событиях.

**Ожидание:** После перезапуска подписки восстанавливаются, события приходят.

## Частые проблемы

- **Подписка не создаётся:** Проверьте, что URL камеры начинается с `http://` или `https://`; логин/пароль верные; камера доступна с хоста сервера (ping, порт 80/8080).
- **События не приходят:** Убедитесь, что камера поддерживает ONVIF Events и PullPoint; в настройках камеры могут быть отключены события или нужные типы.
- **Большая задержка:** Увеличьте частоту опроса (уменьшите `ONVIF_PULL_INTERVAL_MS`), учитывая нагрузку на камеру и сеть.
