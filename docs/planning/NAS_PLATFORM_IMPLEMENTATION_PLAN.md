## 📊 Обзор плана

### Цели реализации

1. **Поддержка основных NAS платформ:**
   - Synology DSM (x86_64, ARM64) - приоритет 1
   - QNAP QTS (x86_64, ARM64) - приоритет 1
   - Asustor ADM (x86_64, ARM64) - приоритет 2
   - TrueNAS SCALE (Docker/Kubernetes) - приоритет 2
   - TrueNAS CORE (FreeBSD) - приоритет 3

2. **Функциональность:**
   - Полная функциональность IP-CSS на NAS
   - Оптимизация для ограниченных ресурсов
   - Использование аппаратного ускорения
   - Интеграция с системными службами NAS

3. **Удобство использования:**
   - Простая установка через пакетные менеджеры
   - Автоматическая настройка
   - Интеграция с веб-интерфейсом NAS (опционально)

### Метрики успеха

- ✅ Поддержка 5+ основных NAS платформ
- ✅ Работа на x86_64 и ARM64 архитектурах
- ✅ Использование аппаратного ускорения где возможно
- ✅ Установка за 5 минут
- ✅ Стабильная работа на бюджетных моделях (2 ГБ RAM, 2 ядра)

// shared/src/commonMain/kotlin/com/company/ipcamera/shared/hardware/HardwareAccelerator.kt

interface HardwareAccelerator {
    suspend fun decodeH264(data: ByteArray): Frame
    suspend fun decodeH265(data: ByteArray): Frame
    suspend fun encodeH264(frame: Frame): ByteArray
    fun isAvailable(): Boolean
    fun getAcceleratorType(): AcceleratorType
}

enum class AcceleratorType {
    INTEL_QUICK_SYNC,    // Intel x86_64
    AMD_VCE_VCN,         // AMD x86_64
    SOFTWARE,             // Fallback
    UNKNOWN
}

object AcceleratorFactory {
    fun create(): HardwareAccelerator {
        return when {
            hasIntelQuickSync() -> IntelQuickSyncAccelerator()
            hasAMDVCA() -> AMDVCAAccelerator()
            else -> SoftwareAccelerator()
        }
    }
}

## 🚨 Риски и митигация

### Риск 1: Сложность интеграции с разными платформами

**Вероятность:** Средняя
**Влияние:** Высокое
**Митигация:**
- Начать с Docker (универсальное решение)
- Использовать единую кодовую базу
- Создать адаптеры для платформо-специфичных функций

### Риск 2: Недоступность тестового оборудования

**Вероятность:** Средняя
**Влияние:** Среднее
**Митигация:**
- Использовать виртуальные машины для базового тестирования
- Партнерство с производителями NAS
- Бета-тестирование с пользователями

### Риск 3: Ограниченные ресурсы бюджетных моделей

**Вероятность:** Высокая
**Влияние:** Среднее
**Митигация:**
- Адаптивная настройка качества
- Ограничение количества потоков
- Оптимизация использования памяти
- Четкие требования к системе

### Риск 4: Задержка сертификации для официальных магазинов

**Вероятность:** Высокая
**Влияние:** Низкое
**Митигация:**
- Публикация через GitHub Releases
- Ручная установка через Package Center
- Параллельная работа над сертификацией
