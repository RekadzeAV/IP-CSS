## 🔧 Как это работает

### Для разработчиков

1. **При внесении значимых изменений:**
   - Обновите TIMELINE.md согласно [руководству](TIMELINE_GUIDE.md)
   - Проверьте изменения скриптом: `./scripts/check-timeline.sh`
   - Добавьте файл в коммит

2. **При создании Pull Request:**
   - Заполните чеклист в шаблоне PR
   - Убедитесь, что TIMELINE.md обновлен (если применимо)

3. **CI автоматически проверит:**
   - Существование TIMELINE.md
   - Структуру файла
   - Актуальность даты обновления

### Когда обновлять обязательно

- ✅ При завершении версии/релиза
- ✅ При завершении крупной задачи
- ✅ При изменении планов (Фазы 1-4)
- ✅ При добавлении новых блокеров
- ✅ При изменении метрик успеха

### Когда обновлять рекомендуется

- 🔵 При начале работы над новой крупной задачей
- 🔵 При изменении архитектуры проекта
- 🔵 При выявлении новых рисков
- 🔵 При изменении сроков или приоритетов
