## Общие проблемы

### Система не запускается

**Симптомы:**
- Приложение не стартует
- Ошибки при запуске
- Сервис падает сразу после запуска

**Возможные причины и решения:**

1. **Отсутствуют переменные окружения**
   ```bash
   # Проверьте наличие обязательных переменных
   echo $JWT_SECRET
   echo $ADMIN_PASSWORD_HASH
   echo $DB_PASSWORD

   # Создайте .env файл из .env.example
   cp .env.example .env
   # Заполните обязательные переменные
   ```

2. **Порты заняты**
   ```bash
   # Проверьте занятые порты
   netstat -tulpn | grep 8080
   lsof -i :8080

   # Измените порты в конфигурации или освободите порты
   ```

3. **Недостаточно прав доступа**
   ```bash
   # Проверьте права на директории
   ls -la data/

   # Установите правильные права
   chmod -R 755 data/
   chown -R user:user data/
   ```

4. **База данных повреждена**
   ```bash
   # Проверьте целостность базы данных
   sqlite3 data/database/surveillance.db "PRAGMA integrity_check;"

   # Восстановите из резервной копии
   cp backup/surveillance.db data/database/surveillance.db
   ```

### Ошибки при установке зависимостей

**Симптомы:**
- Ошибки компиляции
- Отсутствующие библиотеки
- Проблемы с нативными зависимостями

**Решения:**

1. **Очистка кэша Gradle**
   ```bash
   ./gradlew clean
   rm -rf ~/.gradle/caches
   ./gradlew build --refresh-dependencies
   ```

2. **Переустановка зависимостей**
   ```bash
   # Для серверной части
   cd server/api
   ./gradlew clean build

   # Для веб-интерфейса
   cd server/web
   rm -rf node_modules package-lock.json
   npm install
   ```

3. **Проблемы с нативными библиотеками**
   ```bash
   # Убедитесь, что установлены необходимые инструменты
   # Linux
   sudo apt-get install build-essential cmake pkg-config

   # macOS
   brew install cmake pkg-config

   # Windows
   # Установите Visual Studio Build Tools
   ```

## Проблемы с подключением камер

### Камера не обнаруживается

**Симптомы:**
- Камера не появляется в списке при автоматическом поиске
- Ошибка "Camera not found"

**Решения:**

1. **Проверьте сетевую связность**
   ```bash
   # Проверьте доступность камеры
   ping <camera-ip>

   # Проверьте порты
   telnet <camera-ip> 554  # RTSP
   telnet <camera-ip> 80  # HTTP
   ```

2. **Проверьте настройки камеры**
   - Убедитесь, что RTSP включен
   - Проверьте учетные данные
   - Проверьте, что камера поддерживает ONVIF

3. **Ручное добавление камеры**
   ```bash
   # Используйте полный RTSP URL
   rtsp://username:password@camera-ip:554/stream1
   ```

### Ошибки подключения к RTSP потоку

**Симптомы:**
- "Connection refused"
- "Timeout"
- "Authentication failed"

**Решения:**

1. **Проверьте RTSP URL**
   ```bash
   # Тестирование RTSP потока через FFmpeg
   ffmpeg -i rtsp://username:password@camera-ip:554/stream1 -t 5 test.mp4
   ```

2. **Проверьте учетные данные**
   - Убедитесь, что username и password правильные
   - Проверьте, что учетная запись имеет права на просмотр потоков

3. **Проверьте настройки камеры**
   - RTSP должен быть включен
   - Проверьте профили потоков
   - Убедитесь, что камера не перегружена

4. **Проблемы с сетью**
   ```bash
   # Проверьте маршрутизацию
   traceroute <camera-ip>

   # Проверьте firewall
   sudo ufw status
   sudo iptables -L
   ```

### ONVIF подключение не работает

**Симптомы:**
- Ошибка "ONVIF discovery failed"
- Камера не отвечает на ONVIF запросы

**Решения:**

1. **Проверьте WS-Discovery**
   ```bash
   # Используйте ONVIF Device Manager для тестирования
   # Или ONVIF Device Test Tool
   ```

2. **Проверьте URL камеры**
   ```bash
   # Попробуйте различные URL
   http://camera-ip/onvif/device_service
   http://camera-ip/onvif/Media
   ```

3. **Проверьте версию ONVIF**
   - Убедитесь, что камера поддерживает ONVIF 2.0+
   - Проверьте совместимость профилей

## Проблемы с записью видео

### Запись не начинается

**Симптомы:**
- Кнопка "Записать" не работает
- Ошибка "Recording failed to start"

**Решения:**

1. **Проверьте доступность места на диске**
   ```bash
   df -h
   # Убедитесь, что есть достаточно места (минимум 10% свободного)
   ```

2. **Проверьте права на директорию записей**
   ```bash
   ls -la data/recordings/
   chmod -R 755 data/recordings/
   chown -R user:user data/recordings/
   ```

3. **Проверьте настройки записи**
   - Убедитесь, что запись включена в настройках камеры
   - Проверьте формат записи
   - Проверьте качество и битрейт

### Записи повреждены или не воспроизводятся

**Симптомы:**
- Файлы записей не открываются
- Ошибка при воспроизведении
- Записи обрываются

**Решения:**

1. **Проверьте целостность файлов**
   ```bash
   # Проверьте размер файлов
   ls -lh data/recordings/

   # Попробуйте восстановить через FFmpeg
   ffmpeg -i corrupted.mp4 -c copy fixed.mp4
   ```

2. **Проверьте процесс записи**
   ```bash
   # Проверьте, что процесс записи не прерывается
   ps aux | grep ffmpeg
   ```

3. **Проверьте настройки кодека**
   - Убедитесь, что используется поддерживаемый кодек (H.264, H.265)
   - Проверьте настройки битрейта

### Недостаточно места на диске

**Симптомы:**
- Ошибка "Disk full"
- Запись останавливается

**Решения:**

1. **Настройте автоматическую очистку**
   ```yaml
   # В конфигурации
   storage:
     autoCleanup: true
     retentionDays: 30
     minFreeSpaceGB: 10
   ```

2. **Очистите старые записи вручную**
   ```bash
   # Удалите записи старше 30 дней
   find data/recordings/ -type f -mtime +30 -delete
   ```

3. **Используйте внешнее хранилище**
   - Настройте монтирование внешнего диска
   - Используйте сетевые хранилища (NFS, SMB)

## Проблемы с производительностью

### Высокая загрузка CPU

**Симптомы:**
- Система тормозит
- CPU загружен на 100%

**Решения:**

1. **Оптимизируйте настройки записи**
   ```yaml
   recording:
     quality: medium  # Вместо high
     fps: 15  # Вместо 30
     bitrate: 2000  # Снизьте битрейт
   ```

2. **Отключите ненужные функции**
   - Отключите AI-аналитику, если не используется
   - Уменьшите количество одновременных потоков

3. **Используйте аппаратное ускорение**
   ```yaml
   video:
     hardwareAcceleration: true
     codec: h264_nvenc  # Для NVIDIA GPU
   ```

### Высокая загрузка памяти

**Симптомы:**
- Недостаточно памяти
- Система использует swap

**Решения:**

1. **Ограничьте количество потоков**
   ```yaml
   streams:
     maxConcurrent: 4  # Ограничьте количество
   ```

2. **Оптимизируйте буферы**
   ```yaml
   video:
     bufferSize: 1024  # Уменьшите размер буфера
   ```

3. **Увеличьте память системы**
   - Добавьте RAM
   - Используйте более мощный сервер

### Медленная работа веб-интерфейса

**Симптомы:**
- Страницы загружаются медленно
- Интерфейс лагает

**Решения:**

1. **Оптимизируйте запросы к API**
   - Используйте пагинацию
   - Кэшируйте данные
   - Уменьшите частоту обновлений

2. **Проверьте сеть**
   ```bash
   # Проверьте задержку
   ping server-ip

   # Проверьте пропускную способность
   iperf3 -c server-ip
   ```

3. **Используйте CDN для статических ресурсов**
   - Настройте Nginx для раздачи статики
   - Используйте кэширование

## Проблемы с сетью

### Проблемы с WebSocket подключением

**Симптомы:**
- Real-time обновления не работают
- Ошибка "WebSocket connection failed"

**Решения:**

1. **Проверьте настройки прокси**
   ```nginx
   # Nginx конфигурация для WebSocket
   location /api/v1/ws {
       proxy_pass http://backend;
       proxy_http_version 1.1;
       proxy_set_header Upgrade $http_upgrade;
       proxy_set_header Connection "upgrade";
   }
   ```

2. **Проверьте firewall**
   ```bash
   # Разрешите WebSocket порт
   sudo ufw allow 8080/tcp
   ```

3. **Проверьте CORS настройки**
   ```yaml
   cors:
     allowedOrigins:
       - http://localhost:3000
       - https://your-domain.com
   ```

### Проблемы с портами

**Симптомы:**
- Порты недоступны
- Ошибка "Port already in use"

**Решения:**

1. **Найдите процесс, использующий порт**
   ```bash
   # Linux/macOS
   lsof -i :8080

   # Windows
   netstat -ano | findstr :8080
   ```

2. **Измените порты в конфигурации**
   ```yaml
   server:
     port: 8081  # Измените порт
   ```

## Проблемы с AI-аналитикой

### Детекция объектов не работает

**Симптомы:**
- Объекты не обнаруживаются
- Низкая точность детекции

**Решения:**

1. **Проверьте загрузку модели**
   ```bash
   # Убедитесь, что модель загружена
   ls -la data/models/
   ```

2. **Проверьте настройки детекции**
   ```yaml
   analytics:
     objectDetection:
       confidenceThreshold: 0.5  # Уменьшите для большей чувствительности
       model: yolov8n.onnx
   ```

3. **Проверьте качество видео**
   - Убедитесь, что разрешение достаточное
   - Проверьте освещение
   - Убедитесь, что камера правильно настроена

### ANPR не распознает номера

**Симптомы:**
- Номера не распознаются
- Низкая точность распознавания

**Решения:**

1. **Проверьте условия съемки**
   - Освещение должно быть достаточным
   - Угол обзора должен быть оптимальным (15-30 градусов)
   - Расстояние до объекта (3-10 метров)

2. **Настройте параметры ANPR**
   ```yaml
   analytics:
     anpr:
       confidenceThreshold: 0.7
       language: rus+eng
   ```

3. **Проверьте качество камеры**
   - Минимум 2MP, рекомендуется 4MP+
   - Хорошая чувствительность в условиях низкой освещенности

### Высокая загрузка при AI-аналитике

**Симптомы:**
- Система тормозит при включенной аналитике
- Высокая загрузка CPU/GPU

**Решения:**

1. **Используйте GPU ускорение**
   ```yaml
   analytics:
     useGPU: true
     gpuBackend: cuda  # или opencl
   ```

2. **Уменьшите частоту обработки**
   ```yaml
   analytics:
     frameSkip: 2  # Обрабатывать каждый 2-й кадр
   ```

3. **Используйте легковесные модели**
   ```yaml
   analytics:
     model: yolov8n.onnx  # nano вместо large
   ```

## Проблемы с веб-интерфейсом

### Страница не загружается

**Симптомы:**
- Белый экран
- Ошибка 404 или 500

**Решения:**

1. **Проверьте консоль браузера**
   - Откройте Developer Tools (F12)
   - Проверьте ошибки в Console и Network

2. **Проверьте API подключение**
   ```bash
   # Проверьте доступность API
   curl http://localhost:8080/api/v1/health
   ```

3. **Проверьте переменные окружения**
   ```bash
   # Веб-интерфейс
   cat server/web/.env.local
   # NEXT_PUBLIC_API_URL должен быть правильным
   ```

### Видеоплеер не работает

**Симптомы:**
- Видео не воспроизводится
- Ошибка "Failed to load video"

**Решения:**

1. **Проверьте формат потока**
   - Убедитесь, что используется поддерживаемый формат (HLS, WebRTC)
   - Проверьте, что HLS сервер работает

2. **Проверьте CORS настройки**
   ```yaml
   cors:
     allowedOrigins:
       - http://localhost:3000
   ```

3. **Проверьте кодек**
   - Убедитесь, что браузер поддерживает кодек (H.264)

## Логи и диагностика

### Где найти логи

**Серверная часть:**
```bash
# Логи приложения
tail -f data/logs/application.log

# Логи ошибок
tail -f data/logs/error.log

# Docker логи
docker logs ip-camera-surveillance -f
```

**Веб-интерфейс:**
```bash
# Next.js логи
cd server/web
npm run dev
# Логи выводятся в консоль
```

### Уровни логирования

```yaml
# В конфигурации
logging:
  level: DEBUG  # TRACE, DEBUG, INFO, WARN, ERROR
  file: data/logs/application.log
  maxSize: 100MB
  maxFiles: 10
```

### Включение отладочного режима

```bash
# Переменная окружения
export LOG_LEVEL=DEBUG

# Или в .env
LOG_LEVEL=DEBUG
```

### Диагностические команды

```bash
# Проверка здоровья системы
curl http://localhost:8080/api/v1/health

# Проверка статуса камер
curl http://localhost:8080/api/v1/cameras/status

# Проверка использования ресурсов
docker stats ip-camera-surveillance

# Проверка сетевых подключений
netstat -tulpn | grep 8080
```
