## Общий обзор проекта

### Текущий статус

**Общий прогресс:** ~20%

### Архитектурные принципы

Проект следует принципам Clean Architecture:
- ✅ Разделение на слои (Domain, Data, Presentation)
- ✅ Зависимости направлены к абстракциям
- ✅ Кроссплатформенность через Kotlin Multiplatform
- ✅ Использование нативных библиотек для производительности

### Технологический стек

**Кроссплатформенный слой:**
- Kotlin Multiplatform (KMP)
- SQLDelight для базы данных
- Ktor Client для сетевых запросов
- Kotlinx Coroutines для асинхронности

**Платформо-специфичный слой:**
- Android: Jetpack Compose, Hilt, WorkManager
- iOS: SwiftUI, Swinject, BGTaskScheduler
- Desktop: Compose Desktop, Koin
- Web: Next.js, React, Redux Toolkit

**Нативный слой:**
- C++ библиотеки для обработки видео
- OpenCV для компьютерного зрения
- TensorFlow Lite для AI аналитики
- FFI (Foreign Function Interface) для интеграции

**Серверный слой:**
- Ktor для REST API
- Next.js для веб-интерфейса
- Docker для контейнеризации

## Анализ архитектуры

### Слоистая архитектура

```
┌─────────────────────────────────────┐
│     Presentation Layer              │
│  (Android/iOS/Desktop/Web UI)      │
├─────────────────────────────────────┤
│     Domain Layer                    │
│  (Use Cases, Models, Interfaces)   │
├─────────────────────────────────────┤
│     Data Layer                      │
│  (Repositories, Data Sources)      │
├─────────────────────────────────────┤
│     Infrastructure Layer            │
│  (Network, Database, Native)       │
└─────────────────────────────────────┘
```

### Модульная структура

**Основные модули:**
- ✅ `:shared` - Kotlin Multiplatform модуль (общая бизнес-логика)
- ✅ `:core:common` - Базовые типы (Resolution, CameraStatus)
- ✅ `:core:network` - Сетевые клиенты (ONVIF, RTSP, WebSocket, REST API)
- ✅ `:core:license` - Система лицензирования
- ⚠️ `:server:api` - REST API сервер (частично реализован)
- ⚠️ `:server:web` - Веб-интерфейс (частично реализован)
- ❌ `:server:nas` - NAS поддержка (не реализовано)

### Зависимости между модулями

```
android/ios/desktop → shared → core:network, core:license, core:common
                              ↓
                         native (C++ через FFI)
```

**Важно:** Модуль `:core:network` зависит только от `:core:common`, избегая циклических зависимостей.

## Критические пробелы и уязвимости

### Критические пробелы

1. **Отсутствие NAS поддержки (0%)**
   - Детальный анализ в [NAS_PLATFORMS_ANALYSIS.md](NAS_PLATFORMS_ANALYSIS.md)
   - Нет пакетов для основных платформ NAS
   - Нет интеграции с NAS API

2. **Неполная реализация сетевых клиентов**
   - WS-Discovery не реализован в OnvifClient
   - RTSP клиент требует интеграции с нативной библиотекой
   - WebSocket клиент не обрабатывает бинарные сообщения

3. **Отсутствие UI для мобильных платформ**
   - Нет Android UI
   - Нет iOS UI
   - Нет Desktop UI

4. **Неполная реализация лицензирования**
   - Платформо-специфичные реализации используют временные решения
   - Не используется Android Keystore / iOS Keychain

5. **Отсутствие нативных библиотек**
   - C++ код не реализован
   - Нет FFI биндингов
   - Нет интеграции с OpenCV и TensorFlow Lite

### Уязвимости безопасности

1. **Небезопасное хранение лицензий**
   - Android: используется SharedPreferences вместо EncryptedSharedPreferences
   - iOS: используется NSUserDefaults вместо Keychain

2. **Отсутствие аутентификации в API**
   - API endpoints не защищены
   - Нет JWT токенов

3. **Неполная обработка ошибок**
   - Отсутствует стандартизированная обработка ошибок
   - Нет retry логики в некоторых местах

   - Synology: ~35% рынка

   - Asustor: ~12% рынка
   - TrueNAS: ~8% рынка

   - SPK для Synology (x86_64, ARM64)

   - Linux-based (Synology DSM, QNAP QTS, Asustor ADM)

   - Linux + Kubernetes (TrueNAS SCALE)

5. **Рекомендуемый подход:**
   - Начать с универсального Docker решения
   - Добавить нативные пакеты для Synology и QNAP
   - Оптимизировать под каждую платформу
