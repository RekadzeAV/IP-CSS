# Быстрый старт: Версионирование документации

**Версия:** 1.0
**Дата:** January 2026

---

## 🚀 Быстрое использование

### Windows PowerShell

```powershell
# Архивация документа с автоматическим определением даты
.\scripts\archive-documentation.ps1 `
    -Document "docs/ARCHITECTURE.md" `
    -Version "2.0" `
    -NewVersion "3.0"

# С указанием даты
.\scripts\archive-documentation.ps1 `
    -Document "docs/ARCHITECTURE.md" `
    -Version "2.0" `
    -NewVersion "3.0" `
    -Date "2026-01-27"
```

### Linux/macOS

```bash
# Архивация документа с автоматическим определением даты
./scripts/archive-documentation.sh \
    docs/ARCHITECTURE.md \
    2.0 \
    3.0

# С указанием даты
./scripts/archive-documentation.sh \
    docs/ARCHITECTURE.md \
    2.0 \
    3.0 \
    2026-01-27
```

---

## 📋 Что делает скрипт

1. ✅ Создает папку `docs/archive/YYYY-MM-DD/` (если не существует)
2. ✅ Копирует документ в архив
3. ✅ Обновляет версию в документе (например, 2.0 → 3.0)
4. ✅ Обновляет дату последнего обновления
5. ✅ Добавляет информацию о предыдущей версии

---

## 📝 Пример

**До:**
```markdown
# Архитектура системы

**Версия документации:** 2.0
**Дата последнего обновления:** 26 January 2026
```

**После выполнения скрипта:**
```markdown
# Архитектура системы

**Версия документации:** 3.0
**Дата последнего обновления:** 26 January 2026
**Предыдущая версия:** 2.0 (архивирована: 27 января 2025)
```

И файл `docs/archive/2026-01-27/ARCHITECTURE.md` содержит старую версию.

---

## 🔍 Поиск старых версий

Старые версии документов находятся в:
```
docs/archive/YYYY-MM-DD/НАЗВАНИЕ_ДОКУМЕНТА.md
```

Например:
- `docs/archive/2026-01-27/ARCHITECTURE.md` - версия от 27 января 2025

---

## ⚠️ Важно

После архивации документа:

1. ✅ Проверьте обновленный документ
2. ✅ Обновите `DOCUMENTATION_INDEX.md` (если изменилась структура)
3. ✅ Обновите `docs/README.md` (если изменилась навигация)
4. ✅ Обновите `docs/archive/README.md` (добавьте запись о новой версии)
