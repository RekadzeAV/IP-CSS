## 📋 Обзор

Этот документ описывает настройки и параметры работы с документацией в проекте IP-CSS. Проект использует автоматическое управление версиями документации и системные даты.

---

## ⚙️ Основные настройки

### Автоматическое управление версиями

При обновлении документации версия документа **автоматически увеличивается на 1**.

**Формат версии:** `X.Y` или `X.Y.Z`
- **X** - мажорная версия (значительные изменения)
- **Y** - минорная версия (дополнения, улучшения)
- **Z** - патч-версия (исправления ошибок)

**Правило инкремента:**
- При обновлении минорная версия увеличивается на 1
- Пример: `1.0` → `1.1`, `2.5` → `2.6`
- Если есть патч-версия: `1.0.1` → `1.0.2`

### Автоматическая подстановка дат

Все даты в документации **автоматически проставляются системной датой** в формате:
- **Формат:** `DD MMMM YYYY` (например: `26 January 2026`)
- **Локаль:** Русская (ru_RU)

## 🛠️ Gradle задачи для документации

### Обновление версий всех документов

```bash
# Обновить версию всех документов в docs/ (увеличить на 1)
./gradlew updateDocumentationVersion

# Обновить версию конкретного документа
./gradlew incrementDocumentVersion -Pdocument=docs/ARCHITECTURE.md
```

### Обновление дат

```bash
# Обновить даты последнего обновления во всех документах
./gradlew updateDocumentationDate
```

### Подготовка документации

```bash
# Подготовить документацию (обновить версии и даты)
./gradlew prepareDocumentation
```

### Генерация API документации

```bash
# Сгенерировать HTML документацию
./gradlew dokkaHtml

# Сгенерировать Javadoc документацию
./gradlew dokkaJavadoc

# Сгенерировать GitHub Flavored Markdown
./gradlew dokkaGfm

# Полная генерация документации
./gradlew generateDocumentation
```

## 📝 Скрипты архивации документации

### Windows PowerShell

#### Автоматическое увеличение версии

```powershell
# Автоматически определить текущую версию и увеличить на 1
.\scripts\archive-documentation.ps1 -Document "docs/ARCHITECTURE.md" -AutoIncrement

# Ручное указание версий
.\scripts\archive-documentation.ps1 `
    -Document "docs/ARCHITECTURE.md" `
    -Version "2.0" `
    -NewVersion "3.0"
```

#### Параметры скрипта

- `-Document` (обязательный) - путь к документу
- `-Version` (опционально) - текущая версия
- `-NewVersion` (опционально) - новая версия
- `-Date` (опционально) - дата в формате YYYY-MM-DD (по умолчанию текущая дата)
- `-AutoIncrement` (переключатель) - автоматически определить версию и увеличить на 1

### Linux/macOS Bash

#### Автоматическое увеличение версии

```bash
# Автоматически определить текущую версию и увеличить на 1
./scripts/archive-documentation.sh --auto docs/ARCHITECTURE.md

# Ручное указание версий
./scripts/archive-documentation.sh \
    docs/ARCHITECTURE.md \
    2.0 \
    3.0 \
    2026-01-26
```

#### Параметры скрипта

- `--auto` или `-a` (опционально) - автоматически определить версию и увеличить на 1
- `<документ>` (обязательный) - путь к документу
- `<старая_версия>` (опционально) - текущая версия
- `<новая_версия>` (опционально) - новая версия
- `<дата>` (опционально) - дата в формате YYYY-MM-DD (по умолчанию текущая дата)

## 📄 Формат метаданных документации

Каждый документ должен содержать метаданные в начале файла:

```markdown
# Название документа

**Версия документации:** X.Y[.Z]
**Дата создания:** 26 January 2026
**Дата последнего обновления:** 26 January 2026
**Предыдущая версия:** X.Y (архивирована: DD MMMM YYYY) [опционально]

---
```

### Пример

```markdown
# Архитектура системы

**Версия документации:** 2.1
**Дата создания:** 26 January 2026
**Дата последнего обновления:** 26 January 2026
**Предыдущая версия:** 2.0 (архивирована: 26 January 2026)

---
```

## 🔧 Конфигурация Dokka

### Настройки генерации API документации

Dokka настроена для автоматической генерации документации из KDoc комментариев:

- **Версия JDK:** 11
- **Включать приватные API:** Нет (только публичные)
- **Отчеты о недокументированных элементах:** Да
- **Пропускать пустые пакеты:** Да
- **Директория вывода:** `build/dokka/`

### Форматы вывода

1. **HTML** (`dokkaHtml`) - `build/dokka/html/`
2. **Javadoc** (`dokkaJavadoc`) - `build/dokka/javadoc/`
3. **GitHub Flavored Markdown** (`dokkaGfm`) - `build/dokka/gfm/`

## 🔄 Процесс работы с документацией

### Рекомендуемый workflow

1. **Перед изменением документа:**
   ```bash
   # Автоматически архивировать и увеличить версию
   ./scripts/archive-documentation.sh --auto docs/YOUR_DOCUMENT.md
   ```

2. **Внести изменения в документ**

3. **Обновить даты (если нужно):**
   ```bash
   ./gradlew updateDocumentationDate
   ```

4. **Сгенерировать API документацию:**
   ```bash
   ./gradlew dokkaHtml
   ```

## ⚠️ Важные замечания

1. **Всегда используйте автоматическое версионирование** - это гарантирует консистентность
2. **Даты проставляются автоматически** - не редактируйте их вручную
3. **Версии увеличиваются на 1** - это правило применяется ко всем документам
4. **Архивируйте перед значительными изменениями** - используйте скрипты архивации
