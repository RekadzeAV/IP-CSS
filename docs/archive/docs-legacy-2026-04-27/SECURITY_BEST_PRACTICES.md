## Аутентификация и авторизация

### JWT токены

✅ **Рекомендации:**
- Используйте сильные секретные ключи (минимум 32 символа)
- Установите разумное время жизни токенов (15 минут для access, 7 дней для refresh)
- Используйте HTTPS для передачи токенов
- Реализуйте механизм отзыва токенов (blacklist)
- **Храните токены в httpOnly cookies** (реализовано в проекте)

#### Хранение токенов в httpOnly cookies

✅ **Реализовано в проекте:**

**Серверная часть (Kotlin/Ktor):**
- Токены устанавливаются в httpOnly cookies при логине
- Параметры безопасности:
  - `httpOnly = true` - защита от XSS (токены недоступны из JavaScript)
  - `secure = isProduction` - только HTTPS в продакшене
  - `sameSite = Lax` - защита от CSRF атак
- CookieAuthMiddleware автоматически читает токен из cookie и устанавливает в заголовок Authorization
- Токены удаляются из cookies при logout

**Клиентская часть (TypeScript/Next.js):**
- Используется `withCredentials: true` для отправки cookies
- Токены не сохраняются в localStorage или sessionStorage
- Токены недоступны из JavaScript (защита от XSS)

**Преимущества:**
- ✅ Защита от XSS атак (токены недоступны для JavaScript)
- ✅ Автоматическая отправка с каждым запросом
- ✅ Более безопасное хранение по сравнению с localStorage
- ✅ Защита от CSRF через sameSite атрибут

**Настройка CORS:**
```kotlin
install(CORS) {
    allowCredentials = true  // Обязательно для cookies
    // ... другие настройки
}
```

**Пример реализации (сервер):**
```kotlin
// Установка токена в cookie
call.response.cookies.append(
    name = "access_token",
    value = accessToken,
    maxAge = (JwtConfig.accessTokenExpiration / 1000).toInt(),
    httpOnly = true,
    secure = isProduction,
    sameSite = SameSite.Lax,
    path = "/"
)
```

**Пример реализации (клиент):**
```typescript
// Отправка запроса с cookies
const response = await apiClient.post('/auth/login', credentials, {
  withCredentials: true  // Важно для отправки cookies
});
```

❌ **Избегайте:**
- Хранения токенов в localStorage или sessionStorage (уязвимо для XSS)
- Хранения секретов в коде
- Использования одного секрета для всех окружений
- Слишком длительного времени жизни токенов
- Отправки токенов в теле ответа (используйте только cookies)

### Пароли

✅ **Рекомендации:**
- Используйте BCrypt с cost factor 10+
- Требуйте сложные пароли (минимум 12 символов, буквы, цифры, спецсимволы)
- Реализуйте ограничение попыток входа
- Используйте двухфакторную аутентификацию (2FA)

❌ **Избегайте:**
- Хранения паролей в открытом виде
- Использования слабых алгоритмов хеширования (MD5, SHA1)
- Отключения ограничений на попытки входа

### RBAC (Role-Based Access Control)

✅ **Рекомендации:**
- Реализуйте принцип наименьших привилегий
- Разделяйте роли: ADMIN, OPERATOR, USER, VIEWER
- Проверяйте права доступа на каждом endpoint
- Регулярно аудируйте права доступа

## Security Headers

✅ **Рекомендации:**
- Используйте Content-Security-Policy (CSP) для защиты от XSS
- Настройте X-Frame-Options для защиты от clickjacking
- Включите Strict-Transport-Security (HSTS) для принудительного HTTPS
- Используйте X-Content-Type-Options: nosniff для защиты от MIME-sniffing
- Настройте Referrer-Policy для контроля передачи referrer информации
- Используйте Permissions-Policy для ограничения доступа к браузерным API

❌ **Избегайте:**
- Использования `'unsafe-inline'` и `'unsafe-eval'` в production CSP
- Отключения security headers для удобства разработки
- Слишком мягких политик CSP

### Content-Security-Policy (CSP)

✅ **Рекомендации:**
- Используйте `'strict-dynamic'` для скриптов в production
- Ограничьте источники изображений и медиа
- Используйте nonce или hash для inline скриптов
- Настройте `report-uri` для мониторинга нарушений

### Strict-Transport-Security (HSTS)

✅ **Рекомендации:**
- Установите `max-age` минимум на 1 год (31536000 секунд)
- Используйте `includeSubDomains` для защиты всех поддоменов
- Добавьте в HSTS preload list для максимальной защиты
- Применяйте только для HTTPS соединений

**Подробная документация:** См. [SECURITY_HEADERS.md](SECURITY_HEADERS.md)

## Шифрование данных

### Данные в покое

✅ **Рекомендации:**
- Шифруйте базу данных (SQLite encryption, PostgreSQL encryption)
- Шифруйте видеозаписи (AES-256)
- Используйте шифрование файловой системы (LUKS, BitLocker)

### Данные в передаче

✅ **Рекомендации:**
- Используйте TLS 1.3 для всех соединений
- Отключите устаревшие протоколы (TLS 1.0, TLS 1.1)
- Используйте сильные cipher suites
- Реализуйте certificate pinning для мобильных приложений

### Видеопотоки

✅ **Рекомендации:**
- Используйте RTSP over TLS (RTSPS)
- Шифруйте RTSP потоки через SRTP
- Используйте VPN для удаленного доступа

## Сетевая безопасность

### Firewall

✅ **Рекомендации:**
- Откройте только необходимые порты
- Используйте whitelist для доступа к API
- Ограничьте доступ к административным портам
- Реализуйте rate limiting

### CORS

✅ **Рекомендации:**
- Настройте строгие CORS политики
- Укажите конкретные разрешенные домены
- Не используйте `*` для production

### API Security

✅ **Рекомендации:**
- Реализуйте rate limiting (защита от DDoS)
- Используйте API ключи для внешних интеграций
- Валидируйте все входные данные
- Используйте параметризованные запросы (защита от SQL injection)

## Безопасность контейнеров

### Docker

✅ **Рекомендации:**
- Используйте non-root пользователя
- Удалите ненужные capabilities
- Используйте read-only файловую систему где возможно
- Ограничьте ресурсы (CPU, память)
- Используйте минимальные базовые образы

❌ **Избегайте:**
- Использования `SYS_ADMIN` capability
- Отключения seccomp (`seccomp:unconfined`)
- Запуска от root пользователя

### Kubernetes

✅ **Рекомендации:**
- Используйте SecurityContext с ограничениями
- Используйте NetworkPolicies для изоляции
- Реализуйте Pod Security Policies
- Используйте Secrets для хранения секретов

## Управление секретами

✅ **Рекомендации:**
- Используйте секретные хранилища (Vault, AWS Secrets Manager)
- Не храните секреты в Git
- Ротация секретов (регулярная смена)
- Разные секреты для разных окружений

❌ **Избегайте:**
- Хранения секретов в коде
- Коммита .env файлов
- Использования одного секрета везде
