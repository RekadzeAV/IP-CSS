```kotlin
fun createDatabase(driver: SqlDriver): CameraDatabase {
    val database = CameraDatabase(driver)

    // Проверяем, существует ли БД
    val exists = databaseExists(driver)

    if (exists) {
        // Применяем миграции
        CameraDatabase.Schema.migrate(
            driver = driver,
            oldVersion = getCurrentVersion(database),
            newVersion = getTargetVersion()
        )
    } else {
        // Создаем новую БД
        CameraDatabase.Schema.create(driver)
        // Инициализируем версию
        initializeSchemaVersion(database, getTargetVersion())
    }

    return database
}
```

## 🔧 Технические детали

### SQLDelight миграции

SQLDelight автоматически определяет, какие миграции нужно применить, сравнивая:
1. Текущую версию БД (хранится в таблице `schema_version`)
2. Целевую версию схемы (из файла `.sq`)

**Применение миграций:**
```kotlin
CameraDatabase.Schema.migrate(
    driver = driver,
    oldVersion = currentVersion,
    newVersion = targetVersion
)
```

**Создание новой БД:**
```kotlin
CameraDatabase.Schema.create(driver)
```

### Формат миграций (.sqm файлы)

Миграции должны быть названы последовательно: `1.sqm`, `2.sqm`, `3.sqm`, и т.д.

Каждая миграция должна быть идемпотентной (можно применить несколько раз без побочных эффектов).

### Версионирование

- **Версия 1:** Только таблица `camera`
- **Версия 2:** Все таблицы (camera, recording, event, user, setting, notification)
- **Версия 3+:** Будущие изменения

## ⚠️ Риски и митигация

### Риск 1: Потеря данных при миграции
**Митигация:**
- Создание backup перед миграцией (опционально)
- Тщательное тестирование миграций
- Валидация данных после миграции

### Риск 2: Долгая миграция блокирует запуск приложения
**Митигация:**
- Оптимизация миграций (индексы создавать после заполнения данных)
- Показ прогресса миграции пользователю
- Асинхронное выполнение миграций (где возможно)

### Риск 3: Ошибки в миграциях
**Митигация:**
- Тщательное тестирование на тестовых данных
- Валидация миграций перед применением
- Откат изменений при ошибке (опционально)
