## Введение

Данное руководство предназначено для системных администраторов, ответственных за установку, настройку и поддержку системы видеонаблюдения IP-CSS на различных платформах и архитектурах.

### Роль администратора

Администратор системы имеет полный доступ ко всем функциям и настройкам:
- Управление пользователями и ролями
- Конфигурация системы и камер
- Мониторинг производительности
- Резервное копирование и восстановление
- Управление безопасностью

## Поддерживаемые платформы и архитектуры

### Серверные платформы с веб-интерфейсом

#### 1. Микрокомпьютеры ARM (SBC ARM)
- **Архитектура:** ARMv7, ARMv8/aarch64
- **Устройства:** Raspberry Pi (3B+, 4, 5), Orange Pi, Rock64, NanoPi и др.
- **ОС:** Raspberry Pi OS, Ubuntu ARM, Armbian
- **Интерфейс:** Веб-интерфейс (Next.js)
- **Особенности:** Ограниченные ресурсы, рекомендуется для небольших установок (до 4-8 камер)

#### 2. Серверы x86-64
- **Архитектура:** x86-64 (Intel/AMD)
- **ОС:** Linux (Ubuntu 20.04+, Debian 11+, CentOS 8+), Windows Server 2019+, macOS 11.0+
- **Интерфейс:** Веб-интерфейс (Next.js)
- **Особенности:** Высокая производительность, поддержка аппаратного ускорения (Quick Sync, VCE)

#### 3. NAS ARM
- **Архитектура:** ARMv8/aarch64
- **Производители:** Synology (ARM модели), QNAP (ARM модели), Asustor (ARM модели)
- **ОС:** DSM (Synology), QTS (QNAP), ADM (Asustor)
- **Интерфейс:** Веб-интерфейс через пакетное приложение
- **Формат пакетов:** .spk (Synology), .qpkg (QNAP), .apkg (Asustor)

#### 4. NAS x86-64
- **Архитектура:** x86-64
- **Производители:** Synology (x86 модели), QNAP (x86 модели), Asustor (x86 модели), TrueNAS
- **ОС:** DSM, QTS, ADM, TrueNAS Scale
- **Интерфейс:** Веб-интерфейс через пакетное приложение
- **Особенности:** Поддержка аппаратного ускорения, высокая производительность

### Клиентские платформы

#### 5. Android
- **Архитектуры:** ARM, ARM64, x86, x86_64
- **Версия ОС:** Android 8.0+ (API 26+)
- **Интерфейс:** Нативное приложение (Jetpack Compose)
- **Распространение:** Google Play Store, APK

#### 6. iOS/macOS
- **Архитектуры:** ARM64 (Apple Silicon), x86_64 (Intel)
- **Версия ОС:** iOS 14.0+, macOS 11.0+
- **Интерфейс:** Нативное приложение (SwiftUI)
- **Распространение:** App Store, TestFlight

#### 7. Desktop x86-64
- **Архитектура:** x86-64
- **ОС:** Windows 10/11, Linux (Ubuntu, Debian, Fedora), macOS Intel
- **Интерфейс:** Нативное приложение (Compose Desktop)
- **Распространение:** Microsoft Store, пакетные менеджеры, установщики

#### 8. Desktop ARM
- **Архитектура:** ARM64
- **ОС:** Linux ARM64, macOS Apple Silicon
- **Интерфейс:** Нативное приложение (Compose Desktop)
- **Распространение:** Пакетные менеджеры, установщики

## Установка и развертывание

### Быстрая установка (Docker)

**Поддерживаемые платформы:** Linux x86_64, Linux ARM64, macOS x86_64, macOS ARM64, Windows x86_64

```bash
# 1. Скачайте docker-compose.yml
wget https://company.com/docker-compose.yml

# 2. Настройте переменные окружения
cp .env.example .env
nano .env  # Отредактируйте настройки

# 3. Запустите систему
docker-compose up -d

# 4. Проверьте статус
docker-compose ps
docker-compose logs -f
```

### Установка на NAS устройства

#### Synology DSM

1. Откройте **Панель управления** → **Пакеты**
2. Перейдите в **Установка вручную**
3. Выберите скачанный `.spk` файл для вашей архитектуры:
   - `ip-css-synology-arm64.spk` - для ARM моделей
   - `ip-css-synology-x86_64.spk` - для x86 моделей
4. Следуйте инструкциям мастера установки
5. После установки откройте приложение из главного меню

#### QNAP QTS

1. Откройте **App Center**
2. Нажмите **Установка из файла**
3. Выберите `.qpkg` файл для вашей архитектуры:
   - `ip-css-qnap-arm64.qpkg` - для ARM моделей
   - `ip-css-qnap-x86_64.qpkg` - для x86 моделей
4. Дождитесь завершения установки
5. Запустите приложение из App Center

#### TrueNAS Scale

1. Откройте **Apps** → **Available Applications**
2. Найдите "IP-CSS" или установите из файла
3. Настройте параметры развертывания
4. Запустите приложение

### Установка на серверы Linux

#### Ubuntu/Debian

```bash
# Добавьте репозиторий
curl -fsSL https://company.com/repo/ubuntu/gpg | sudo apt-key add -
echo "deb https://company.com/repo/ubuntu focal main" | sudo tee /etc/apt/sources.list.d/ip-css.list

# Установите пакет
sudo apt update
sudo apt install ip-camera-surveillance

# Запустите службу
sudo systemctl enable ip-css
sudo systemctl start ip-css
```

#### RHEL/Fedora/CentOS

```bash
# Добавьте репозиторий
sudo dnf config-manager --add-repo https://company.com/repo/rhel/ip-css.repo

# Установите пакет
sudo dnf install ip-camera-surveillance

# Запустите службу
sudo systemctl enable ip-css
sudo systemctl start ip-css
```

### Установка на микрокомпьютеры ARM (Raspberry Pi)

```bash
# Установите зависимости
sudo apt update
sudo apt install -y docker.io docker-compose

# Скачайте и запустите
git clone https://github.com/company/ip-css.git
cd ip-css
docker-compose up -d
```

## Начальная настройка системы

### Первый вход

1. Откройте веб-интерфейс: `http://<IP-адрес>:8080`
2. Войдите с учетными данными по умолчанию:
   - **Логин:** `admin`
   - **Пароль:** `admin`
3. **Важно:** Смените пароль администратора при первом входе!

### Настройка базовых параметров

#### 1. Настройка сети

Перейдите в **Настройки** → **Сеть**:

- **Порт HTTP:** 8080 (по умолчанию)
- **Порт HTTPS:** 8443 (по умолчанию)
- **Внешний URL:** для доступа извне (опционально)
- **SSL сертификат:** для HTTPS (рекомендуется)

#### 2. Настройка хранилища

Перейдите в **Настройки** → **Хранилище**:

- **Путь к записям:** `/var/lib/ip-css/recordings` (Linux) или `C:\ProgramData\IP-CSS\recordings` (Windows)
- **Максимальный размер:** укажите лимит или оставьте без ограничений
- **Срок хранения:** количество дней (по умолчанию: 30)
- **Автоматическая очистка:** включить/выключить

#### 3. Настройка базы данных

Система использует SQLite по умолчанию. Для больших установок рекомендуется PostgreSQL:

```yaml
# config.yaml
database:
  type: postgresql  # или sqlite
  host: localhost
  port: 5432
  name: ipcss
  username: ipcss_user
  password: secure_password
```

## Управление пользователями и правами доступа

### Роли пользователей

Система поддерживает следующие роли:

1. **ADMIN** - Полный доступ ко всем функциям
2. **OPERATOR** - Управление камерами, просмотр записей, управление событиями
3. **VIEWER** - Просмотр камер и записей (только чтение)
4. **GUEST** - Ограниченный доступ (только просмотр)

### Создание пользователя

1. Перейдите в **Пользователи** → **Добавить пользователя**
2. Заполните форму:
   - **Имя пользователя:** уникальный логин
   - **Email:** адрес электронной почты
   - **Полное имя:** отображаемое имя
   - **Роль:** выберите роль из списка
   - **Пароль:** установите надежный пароль
3. Нажмите **Создать**

### Управление правами доступа

Для каждой роли можно настроить дополнительные разрешения:

1. Перейдите в **Пользователи** → **Роли и права**
2. Выберите роль
3. Настройте разрешения:
   - `cameras.view` - просмотр камер
   - `cameras.manage` - управление камерами
   - `recordings.view` - просмотр записей
   - `recordings.export` - экспорт записей
   - `events.view` - просмотр событий
   - `events.manage` - управление событиями
   - `settings.view` - просмотр настроек
   - `settings.manage` - управление настройками
   - `users.view` - просмотр пользователей
   - `users.manage` - управление пользователями

### Интеграция с Active Directory / LDAP

> **⚠️ Статус:** Функция находится в разработке. См. [USER_MANAGEMENT_SSO_KERBEROS_ANALYSIS.md](USER_MANAGEMENT_SSO_KERBEROS_ANALYSIS.md)

Планируемая функциональность:
- Интеграция с Active Directory
- Поддержка LDAP
- SSO (Single Sign-On) через SAML/OIDC
- Kerberos аутентификация
- Синхронизация пользователей с доменом
- Авторизация на основе групп домена

## Конфигурация системы

### Конфигурационный файл

Основной файл конфигурации: `config.yaml` (или `config.json`)

```yaml
server:
  port: 8080
  host: 0.0.0.0
  ssl:
    enabled: false
    cert_path: /path/to/cert.pem
    key_path: /path/to/key.pem

database:
  type: sqlite  # или postgresql
  path: /var/lib/ip-css/database.db
  # Для PostgreSQL:
  # host: localhost
  # port: 5432
  # name: ipcss
  # username: user
  # password: pass

storage:
  recordings_path: /var/lib/ip-css/recordings
  max_size_gb: 1000
  retention_days: 30
  auto_cleanup: true

features:
  analytics: true
  anpr: false
  notifications: true
  cloud_sync: false

logging:
  level: INFO  # DEBUG, INFO, WARN, ERROR
  file: /var/log/ip-css/app.log
  max_size_mb: 100
  max_files: 10
```

### Настройка камер

#### Добавление камеры

1. Перейдите в **Камеры** → **Добавить камеру**
2. Выберите способ добавления:
   - **Автообнаружение** (ONVIF WS-Discovery) - система найдет камеры в сети
   - **Вручную** - введите параметры камеры
3. Заполните параметры:
   - **Название:** отображаемое имя камеры
   - **RTSP URL:** `rtsp://username:password@ip:port/stream`
   - **ONVIF URL:** `http://ip:port/onvif/device_service` (опционально)
   - **Учетные данные:** логин и пароль
4. Нажмите **Тест подключения** для проверки
5. Нажмите **Сохранить**

#### Настройка записи

Для каждой камеры можно настроить:

- **Режим записи:**
  - Непрерывная запись
  - Запись по событиям
  - Запись по расписанию
- **Качество записи:** разрешение, битрейт, FPS
- **Формат:** MP4, MKV, AVI
- **Сжатие:** H.264, H.265

#### Настройка аналитики

- **Детекция движения:** включить/выключить, чувствительность
- **Детекция объектов:** типы объектов (человек, автомобиль, животное)
- **ANPR** (распознавание номеров): включить/выключить
- **Распознавание лиц:** включить/выключить

### Настройка уведомлений

Перейдите в **Настройки** → **Уведомления**:

- **Email:** SMTP настройки
- **SMS:** интеграция с SMS-шлюзом
- **Push:** настройка push-уведомлений
- **Telegram:** токен бота
- **Webhook:** URL для отправки событий

## Резервное копирование и восстановление

### Автоматическое резервное копирование

Настройте cron задачу (Linux):

```bash
# Ежедневное резервное копирование в 2:00
0 2 * * * /usr/local/bin/ip-css-backup.sh
```

Скрипт резервного копирования:

```bash
#!/bin/bash
BACKUP_DIR="/backup/ip-css"
DATE=$(date +%Y%m%d_%H%M%S)

# Создать директорию
mkdir -p "$BACKUP_DIR"

# Резервная копия базы данных
sqlite3 /var/lib/ip-css/database.db ".backup '$BACKUP_DIR/db_$DATE.db'"

# Резервная копия конфигурации
cp /etc/ip-css/config.yaml "$BACKUP_DIR/config_$DATE.yaml"

# Резервная копия настроек камер (если хранятся отдельно)
# tar -czf "$BACKUP_DIR/cameras_$DATE.tar.gz" /var/lib/ip-css/cameras/

# Удалить резервные копии старше 30 дней
find "$BACKUP_DIR" -type f -mtime +30 -delete
```

### Ручное резервное копирование

1. Перейдите в **Настройки** → **Резервное копирование**
2. Нажмите **Создать резервную копию**
3. Выберите компоненты для резервного копирования:
   - База данных
   - Конфигурация
   - Настройки камер
   - Записи (опционально)
4. Нажмите **Скачать** или сохраните на сервере

### Восстановление из резервной копии

1. Перейдите в **Настройки** → **Резервное копирование**
2. Нажмите **Восстановить**
3. Загрузите файл резервной копии
4. Выберите компоненты для восстановления
5. Нажмите **Восстановить**

**⚠️ Внимание:** Восстановление перезапишет текущие данные!

## Безопасность

### Рекомендации по безопасности

1. **Смените пароль администратора** при первом входе
2. **Используйте HTTPS** для доступа к веб-интерфейсу
3. **Ограничьте доступ** к портам системы через файрвол
4. **Регулярно обновляйте** систему
5. **Используйте надежные пароли** для всех пользователей
6. **Включите двухфакторную аутентификацию** (2FA) для администраторов
7. **Настройте резервное копирование** и регулярно проверяйте его
8. **Мониторьте логи** на предмет подозрительной активности

### Настройка HTTPS

1. Получите SSL сертификат (Let's Encrypt, коммерческий)
2. Сохраните сертификат и ключ на сервере
3. Обновите `config.yaml`:
```yaml
server:
  ssl:
    enabled: true
    cert_path: /path/to/cert.pem
    key_path: /path/to/key.pem
```
4. Перезапустите сервер

### Настройка файрвола

#### Linux (iptables)

```bash
# Разрешить HTTP
sudo iptables -A INPUT -p tcp --dport 8080 -j ACCEPT

# Разрешить HTTPS
sudo iptables -A INPUT -p tcp --dport 8443 -j ACCEPT

# Заблокировать все остальное
sudo iptables -A INPUT -j DROP
```

#### Windows Firewall

1. Откройте **Брандмауэр Windows**
2. Создайте правило для входящих подключений
3. Разрешите порты 8080 (HTTP) и 8443 (HTTPS)

## Устранение неполадок

### Проблемы с подключением к камерам

**Симптом:** Камера показывает статус "OFFLINE" или "ERROR"

**Решения:**
1. Проверьте RTSP URL и учетные данные
2. Убедитесь, что камера доступна в сети (ping)
3. Проверьте порты (обычно 554 для RTSP)
4. Проверьте настройки файрвола на камере
5. Используйте **Тест подключения** в интерфейсе

### Проблемы с записью

**Симптом:** Записи не создаются или прерываются

**Решения:**
1. Проверьте доступное место на диске
2. Проверьте права доступа к директории записей
3. Проверьте логи на наличие ошибок
4. Убедитесь, что камера передает поток

### Проблемы с производительностью

**Симптом:** Медленная работа системы, задержки видео

**Решения:**
1. Проверьте использование ресурсов (CPU, RAM)
2. Уменьшите количество одновременных потоков
3. Снизьте качество записи
4. Используйте аппаратное ускорение (если доступно)
5. Рассмотрите обновление оборудования

### Логи и диагностика

#### Просмотр логов

**Веб-интерфейс:**
1. Перейдите в **Настройки** → **Логи**
2. Выберите уровень логирования (DEBUG, INFO, WARN, ERROR)
3. Фильтруйте по компонентам или времени

**Командная строка (Linux):**
```bash
# Все логи
tail -f /var/log/ip-css/app.log

# Только ошибки
grep ERROR /var/log/ip-css/app.log

# Логи за последний час
journalctl -u ip-css --since "1 hour ago"
```

```bash
# Все логи
docker-compose logs -f

# Логи конкретного сервиса
docker-compose logs -f api
```
