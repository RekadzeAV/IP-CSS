## Типы и конструкции IP-камер

### По месту установки

#### Уличные камеры
- **Купольные (Dome):**
  - Скрытое крепление
  - Защита от вандализма
  - IP66/IP67 защита
  - Примеры: Hikvision DS-2CD2xxx, Dahua IPC-HDWxxxx

- **Цилиндрические (Bullet):**
  - Открытое крепление
  - Дальнобойная ИК-подсветка
  - IP66/IP67 защита
  - Примеры: Hikvision DS-2CD2xxx, Dahua IPC-HFWxxxx

#### Внутренние камеры
- Компактные размеры
- Разнообразие форм
- Меньшая защита (IP20-IP54)
- WiFi варианты

### По функциональности

#### Фиксированные камеры
- Статический обзор
- Оптимальное соотношение цена/качество
- Простая установка

#### PTZ камеры (Pan-Tilt-Zoom)
- Управление поворотом и наклоном
- Оптический зум
- Предустановки (Presets)
- Паттерны и туры
- Примеры: Hikvision DS-2DE4xxx, Dahua SD5xxx

#### Панорамные камеры
- 360° обзор
- Разрешение до 12 МП
- Цифровой PTZ (ePTZ)
- Примеры: Hikvision DS-2CD6xxx

#### Камеры с переменным фокусом (Varifocal)
- Ручная или моторизованная настройка фокуса
- Гибкость в установке
- Оптимизация зоны обзора

## Ключевые технические характеристики

### Разрешение и качество изображения

#### Разрешение матрицы
- **1 МП (720p):** Бюджетный вариант, достаточный для базового наблюдения
- **2 МП (1080p):** Наиболее популярный вариант, баланс качества и объема
- **3-4 МП (1440p-2160p):** Улучшенная детализация
- **5 МП и выше:** Высокое качество, требует больше ресурсов

#### Технологии улучшения изображения

**WDR (Wide Dynamic Range):**
- Диапазон: 100-140 дБ
- Четкое изображение при контровом свете
- Критично для входов/окон

**EXIR (Extended Infrared):**
- Дальность ИК-подсветки: 20-50+ метров
- Равномерное освещение
- Улучшенное ночное видение

**3D DNR (Digital Noise Reduction):**
- Подавление шума
- Улучшение качества при низкой освещенности

**BLC (Back Light Compensation):**
- Компенсация задней подсветки
- Улучшение видимости объектов на светлом фоне

**ROI (Region of Interest):**
- Выделение зон особого внимания
- Оптимизация битрейта
- Повышение качества в важных областях

### Кодеки и сжатие

#### Видеокодеки
- **H.264 (AVC):** Наиболее распространенный, хорошая совместимость
- **H.265 (HEVC):** Улучшенное сжатие (~50% меньше битрейт), требует больше ресурсов
- **MJPEG:** Простой, но высокий битрейт, используется для стриминга
- **H.264+ / H.265+:** Проприетарные улучшения производителей

#### Аудиокодеки
- **G.711 (PCM):** Базовый, широко поддерживается
- **G.726:** Сжатие аудио
- **AAC:** Современный, лучшее качество

### Сетевые возможности

#### PoE (Power over Ethernet)
- **PoE (802.3af):** До 15.4W
- **PoE+ (802.3at):** До 25.5W
- **PoE++ (802.3bt):** До 60W (для PTZ камер)
- Преимущества: Один кабель для питания и данных

#### WiFi
- **802.11n (2.4 GHz):** Базовый вариант
- **802.11ac (5 GHz):** Высокая скорость
- **802.11ax (WiFi 6):** Современный стандарт
- Важно: Стабильность зависит от сигнала

#### Сетевые протоколы
- **RTSP:** Видеопоток в реальном времени
- **HTTP/HTTPS:** Веб-интерфейс, API, MJPEG стрим
- **ONVIF:** Стандартизированное управление
- **RTP/RTCP:** Транспорт для RTSP
- **WebRTC:** Современный стриминг через браузер

### Интеллектуальные функции

#### Детекция движения
- **Базовый:** Пиксельный анализ
- **Улучшенный:** Анализ областей, фильтрация ложных срабатываний
- **AI-детекция:** Классификация объектов (человек, транспорт, животное)

#### AcuSense (Hikvision) / Smart Motion (Dahua)
- Различение людей и транспортных средств
- Снижение ложных тревог
- Точная детекция

#### Двусторонняя аудиосвязь
- Встроенный микрофон
- Встроенный динамик
- Удаленная связь

#### Аналитика
- Подсчет людей
- Детекция пересечения линии
- Детекция вторжения в зону
- Распознавание лиц (в премиум моделях)

## Протоколы и стандарты

### ONVIF (Open Network Video Interface Forum)

#### Профили ONVIF
- **Profile S:** Базовый стриминг видео/аудио
- **Profile T:** Расширенный стриминг (H.265, улучшенное аудио)
- **Profile G:** Запись и хранение
- **Profile M:** Аналитика и метаданные
- **Profile Q:** Быстрая настройка (без паролей)

#### ONVIF сервисы
- **Device Management:** Информация об устройстве
- **Media:** Получение URI потоков
- **PTZ:** Управление поворотом/наклоном/зумом
- **Imaging:** Настройка изображения
- **Event:** События и уведомления
- **Analytics:** Аналитические данные

### RTSP (Real Time Streaming Protocol)

#### Формат URL
```
rtsp://[username]:[password]@[ip]:[port]/[path]
```

#### Типичные пути потоков
- Hikvision: `/Streaming/Channels/[channel]01` (Main), `02` (Sub)
- Dahua: `/cam/realmonitor?channel=1&subtype=0` (Main), `subtype=1` (Sub)
- Axis: `/axis-media/media.amp`
- Общий: `/stream1`, `/video`, `/live`

#### Методы RTSP
- `DESCRIBE` - получение описания потока
- `SETUP` - настройка сессии
- `PLAY` - начало воспроизведения
- `PAUSE` - пауза
- `TEARDOWN` - завершение сессии

### HTTP/HTTPS API

#### Типичные эндпоинты
- **MJPEG стрим:** `http://[ip]/mjpeg_stream`
- **Снимок:** `http://[ip]/snapshot.jpg`
- **API:** `http://[ip]/cgi-bin/[api].cgi`
- **ONVIF:** `http://[ip]:80/onvif/device_service`

### Аутентификация

#### Типы аутентификации
- **Basic Authentication:** Простая, но небезопасная
- **Digest Authentication:** Более безопасная, используется в ONVIF
- **Token-based:** Современный подход (Axis, некоторые модели)
- **Certificate-based:** Высокая безопасность

## Особенности настройки и использования

### Преимущества IP-камер

1. **Цифровая передача:**
   - Отсутствие потерь качества
   - Защищенность данных
   - Совместимость со стандартными сетями

2. **Масштабируемость:**
   - Легкое добавление новых камер
   - Централизованное управление
   - Гибкая архитектура

3. **Удаленный доступ:**
   - Доступ из любой точки мира
   - Мобильные приложения
   - Веб-интерфейс

4. **Интеллектуальные функции:**
   - AI-аналитика
   - Детекция событий
   - Автоматические уведомления

5. **Гибкость:**
   - Множественные видеопотоки
   - Настройка качества
   - Интеграция с другими системами

### Недостатки и ограничения

1. **Стоимость:**
   - Выше цена по сравнению с аналоговыми
   - Требуется сетевая инфраструктура
   - NVR/сервер для записи

2. **Технические ограничения:**
   - Максимальная длина кабеля: 100 метров (Ethernet)
   - Задержка сигнала: 100-500ms (зависит от сети)
   - Требования к пропускной способности сети

3. **Сложность настройки:**
   - Требуются знания сетевых технологий
   - Настройка безопасности
   - Управление множеством параметров

4. **Зависимость от производителя:**
   - Облачные сервисы могут прекратить работу
   - Проприетарные функции
   - Обновления прошивок

### Нюансы настройки

#### Сетевая настройка
- **Статический IP vs DHCP:** Рекомендуется статический для стабильности
- **VLAN:** Изоляция камер в отдельной сети
- **QoS:** Приоритизация видеотрафика
- **Bandwidth:** Расчет пропускной способности (битрейт × количество камер)

#### Безопасность
- **Смена паролей по умолчанию:** Критично важно
- **Отключение неиспользуемых сервисов:** Снижение поверхности атаки
- **Обновления прошивок:** Регулярные обновления безопасности
- **VPN:** Защищенный доступ извне
- **Firewall:** Ограничение доступа

#### Оптимизация производительности
- **Множественные потоки:** Main (высокое качество) + Sub (низкое качество)
- **ROI:** Выделение важных зон
- **Адаптивный битрейт:** Автоматическая регулировка
- **Кэширование:** Локальное кэширование для быстрого доступа

#### Типичные проблемы

1. **Проблемы подключения:**
   - Неправильные учетные данные
   - Блокировка firewall
   - Несовместимость протоколов

2. **Проблемы качества:**
   - Недостаточная пропускная способность
   - Плохое освещение
   - Неправильные настройки кодека

3. **Проблемы стабильности:**
   - Перегрузка сети
   - Проблемы с питанием (PoE)
   - Устаревшая прошивка

#### 1. Протоколы и стандарты

##### RTSP (Real Time Streaming Protocol)
**Статус реализации:** ✅ **Полностью реализовано (100%)** - Завершено 26 января 2026

**Реализовано:**
- ✅ Полная нативная C++ реализация RTSP протокола (OPTIONS, DESCRIBE, SETUP, PLAY, PAUSE, TEARDOWN)
- ✅ RTP/RTCP обработка (парсинг, статистика, отправка RR)
- ✅ Декодирование видео/аудио (H.264, H.265, MJPEG, AAC, PCMU, PCMA, MP3)
- ✅ Аутентификация (Basic, Digest с поддержкой stale nonce)
- ✅ Автоматическое переподключение
- ✅ Kotlin обертка с полной структурой
- ✅ JNI биндинги для Android
- ✅ Интеграция с видеоплеером (HLS конвертация через FFmpeg)
- ✅ Поддержка множественных потоков (Main/Sub через разные URL)

**Требуется доработать:**
- ⚠️ Автоматическое определение путей потоков для разных производителей (Hikvision, Dahua, Axis)
- ⚠️ Адаптивное качество потока (автоматическое переключение Main/Sub)
- ⚠️ Тестирование на различных архитектурах и платформах (iOS, Desktop Native)

**Документация:** [RTSP_CLIENT.md](RTSP_CLIENT.md), [RTSP_CLIENT_IMPLEMENTATION_STATUS.md](RTSP_CLIENT_IMPLEMENTATION_STATUS.md)

##### ONVIF (Open Network Video Interface Forum)
**Статус реализации:** 🟡 **Частично реализовано (~70%)**

**Реализовано:**
- ✅ Базовые методы (getCapabilities, getDeviceInformation, getProfiles, getStreamUri)
- ✅ PTZ управление (movePtz, stopPtz)
- ✅ testConnection() - реализован
- ✅ WS-Discovery улучшен (обнаружение камер работает, но требует доработки)
- ✅ Digest Authentication (частично)
- ✅ Интеграция с CameraRepository

**Требуется доработать:**
- ⚠️ Полная поддержка Profile S, T, G, M (частично реализовано)
- ⚠️ WS-Discovery - улучшить надежность и скорость обнаружения
- ⚠️ Полноценный XML парсинг (сейчас используется упрощенный через regex)
- ⚠️ Полная поддержка PTZ управления (предустановки, паттерны, туры)
- ❌ Поддержка событий (Event service) - не реализовано
- ❌ Поддержка аналитики (Analytics service) - не реализовано
- ❌ Imaging service для настройки изображения - не реализовано

**Документация:** [ONVIF_CLIENT.md](ONVIF_CLIENT.md), [ONVIF_CLIENT_IMPLEMENTATION_PLAN.md](ONVIF_CLIENT_IMPLEMENTATION_PLAN.md)

##### HTTP/HTTPS протоколы

- ✅ HLS генерация для веб-плеера (HlsGeneratorService)

**Требуется добавить:**

- ❌ HTTP API для производителей (Hikvision ISAPI, Dahua API, Axis VAPIX)
- ❌ Получение снимков через HTTP (`http://[ip]/snapshot.jpg`)
- ❌ Управление настройками камер через HTTP API производителей

**Приоритет:** Средний (RTSP покрывает большинство случаев, HTTP API нужен для расширенных функций)

#### 3. Функциональность камер

##### Обнаружение камер
**Статус реализации:** 🟡 **Частично реализовано (~60%)**

**Реализовано:**
- ✅ WS-Discovery через ONVIF (работает, но требует улучшения)
- ✅ Интеграция в CameraRepository.discoverCameras()
- ✅ UI компонент для обнаружения (CameraDiscoveryDialog) - веб-интерфейс
- ✅ Автоматическое добавление обнаруженных камер

**Требуется доработать:**
- ⚠️ WS-Discovery - улучшить надежность и скорость (сейчас ~40-60% успешных обнаружений)
- ❌ UPnP обнаружение - для камер без ONVIF
- ❌ Сканирование сети - поиск камер по IP диапазону
- ⚠️ Ручной ввод - мастер добавления камеры (частично реализован в UI)

##### Управление потоками
**Статус реализации:** 🟡 **Частично реализовано (~70%)**

**Реализовано:**
- ✅ Поддержка множественных потоков через RTSP (Main/Sub через разные URL)
- ✅ Audio stream - декодирование AAC, PCMU, PCMA, MP3
- ✅ HLS генерация для веб-плеера (конвертация RTSP в HLS)
- ✅ Управление качеством потока (LOW, MEDIUM, HIGH, ULTRA)
- ✅ VideoStreamService - управление трансляцией потоков

**Требуется доработать:**
- ⚠️ Автоматическое определение и переключение Main/Sub потоков
- ❌ Metadata stream - обработка метаданных из потока
- ❌ Адаптивное качество - автоматическое переключение между потоками
- ❌ ROI (Region of Interest) - выделение зон особого внимания
- ⚠️ Оптимизация битрейта - автоматическая регулировка

##### PTZ управление
