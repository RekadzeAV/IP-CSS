# Руководство по ведению временной шкалы проекта

**Версия:** Alfa-0.0.1  
**Дата создания:** 26 January 2026

---

## 📋 Обзор

Файл `TIMELINE.md` является **обязательным** для ведения в проекте IP-CSS. Он содержит историю развития проекта, текущее состояние и планы на будущее.

**Внимание:** Временная шкала должна обновляться при каждом значимом изменении в проекте.

---

## 🎯 Назначение временной шкалы

Временная шкала помогает:
- 📊 Отслеживать прогресс проекта
- 🗓️ Планировать будущие этапы разработки
- 📈 Визуализировать историю проекта
- 🎯 Синхронизировать работу команды
- 📝 Документировать ключевые решения и изменения

---

## ✅ Когда обновлять TIMELINE.md

### Обязательные обновления:

1. **При завершении версии/релиза:**
   - Переместить изменения из раздела "В процессе" в "Завершено"
   - Обновить дату релиза
   - Добавить новую версию в раздел "Прошлое"

2. **При завершении крупной задачи:**
   - Обновить статус в разделе "Настоящее"
   - Изменить процент прогресса, если применимо
   - Обновить дату "Последнее обновление"

3. **При изменении планов (Фазы 1-4):**
   - Обновить оценки времени
   - Добавить/изменить задачи
   - Обновить критерии готовности

4. **При добавлении новых блокеров:**
   - Добавить в раздел "Критические блокеры продакшена"
   - Обновить приоритеты

5. **При изменении метрик успеха:**
   - Обновить раздел "Метрики успеха"
   - Добавить новые критерии оценки

### Рекомендуемые обновления:

- При начале работы над новой крупной задачей
- При изменении архитектуры проекта
- При выявлении новых рисков или вызовов
- При изменении сроков или приоритетов

---

## 📝 Формат обновлений

### Структура записи:

```markdown
### [Версия X.Y.Z] - YYYY-MM-DD

**Статус:** ✅ Завершено / 🟡 В процессе / ❌ Отменено

**Достижения:**
- ✅ Задача 1
- ✅ Задача 2
- ⚠️ Задача 3 (частично)

**Изменения:**
- Изменение 1
- Изменение 2

**Известные проблемы:**
- Проблема 1 (если есть)
```

### Легенда статусов:

- ✅ **Завершено** - Компонент полностью реализован и протестирован
- 🟡 **Частично** - Компонент частично реализован, требует доработки
- ⚠️ **В процессе** - Компонент находится в разработке
- ❌ **Не выполнено** - Компонент не реализован или отменен
- 📋 **Запланировано** - Компонент запланирован к реализации

## 🔄 Процесс обновления

### Шаг 1: Определите тип изменения

- [ ] Релиз новой версии
- [ ] Завершение крупной задачи
- [ ] Изменение планов
- [ ] Обновление статуса

### Шаг 2: Найдите соответствующий раздел

- **Прошлое** - для завершенных версий
- **Настоящее** - для текущей разработки
- **Будущее** - для планов и фаз

### Шаг 3: Обновите информацию

Следуйте формату и структуре существующих записей. Будьте конкретны и кратки.

### Шаг 4: Обновите метаданные

- Дата "Последнее обновление" в конце файла
- Процент прогресса, если изменился
- Связанные документы

### Шаг 5: Проверьте согласованность

- [ ] Все ссылки работают
- [ ] Форматирование корректно
- [ ] Нет противоречий с другими документами
- [ ] Процент прогресса обновлен
- [ ] Даты указаны корректно

## 📊 Примеры обновлений

### Пример 1: Завершение задачи

**До:**
```markdown
- ⚠️ OnvifClient (частично - ~40%, WS-Discovery частично реализован)
```

**После:**
```markdown
- ✅ OnvifClient (WS-Discovery полностью реализован, ~80% завершено)
```

### Пример 2: Добавление новой версии

**Добавить в раздел "Прошлое":**
```markdown
### Версия Alfa-0.0.1 - January 2026
**🎯 MVP Release**

**Достижения:**
- ✅ Завершен REST API сервер
- ✅ Завершен веб-интерфейс
- ✅ Реализован RTSP клиент
- ✅ Базовая система записи

**Статус:** ✅ Завершено
```

### Пример 3: Обновление прогресса

**До:**
```markdown
**Текущий прогресс:** ~20% от MVP
```

**После:**
```markdown
**Текущий прогресс:** ~35% от MVP
```

## 🚫 Чего избегать

❌ **Не добавляйте:**
- Личные мнения или комментарии
- Избыточную детализацию (используйте CHANGELOG.md)
- Информацию без подтверждения
- Устаревшие данные

❌ **Не удаляйте:**
- Исторические записи (они важны для понимания проекта)
- Структуру разделов
- Метаданные файла

❌ **Не изменяйте:**
- Формат без обсуждения с командой
- Даты в исторических записях
- Процент прогресса без реальных изменений

## ✅ Чеклист для обновления

Перед коммитом изменений в TIMELINE.md проверьте:

- [ ] Обновлена соответствующая секция (Прошлое/Настоящее/Будущее)
- [ ] Использованы правильные статусы (✅/🟡/⚠️/❌)
- [ ] Обновлена дата "Последнее обновление"
- [ ] Обновлен процент прогресса (если применимо)
- [ ] Добавлены ссылки на связанные документы (если нужно)
- [ ] Проверено форматирование Markdown
- [ ] Нет орфографических ошибок
- [ ] Информация согласована с CHANGELOG.md
- [ ] Информация согласована с CURRENT_STATUS.md
- [ ] Изменения соответствуют реальному состоянию проекта

## 📅 Регулярные обновления

### Еженедельные обновления (рекомендуется):

- Обновление статуса текущих задач
- Корректировка процента прогресса
- Добавление новых блокеров (если есть)

### При каждом релизе (обязательно):

- Перемещение завершенных задач в историю
- Обновление версии
- Обновление дат

### При изменении планов (обязательно):

- Обновление фаз и оценок времени
- Изменение приоритетов
- Обновление метрик успеха
