### 4.3.3: Оптимизация производительности многокамерного просмотра

**Цель:** Оптимизировать производительность при одновременном просмотре множественных камер.

**Текущее состояние:** Базовая реализация работает, но требует оптимизации для стабильной работы с 16 камерами.

**Прогресс на 2026-03-27 (фактически реализовано):**
- ✅ Введена приоритизация потоков `HIGH/NORMAL/BACKGROUND` с авто-pause для background.
- ✅ Добавлена viewport-visibility логика + grace period (режимы `AUTO/CUSTOM`) с persist.
- ✅ Реализована авто-настройка grace по layout (`GRID_4/9/16`) и UI-индикаторы режима.
- ✅ Оптимизирован рендер `VideoPlayerFrame`: убраны промежуточные `BufferedImage` (меньше memory churn).
- ✅ Добавлены runtime-метрики рендера: `renderFps`, `droppedFrames`, агрегация в telemetry header.
- ✅ Добавлен UI-индикатор `Lazy paused` (число плиток вне viewport с lazy-render в `GRID_9/16`).
- ✅ Добавлено подавление шумовых апдейтов телеметрии (throttling/dedup) для 9/16 сеток.
- ✅ Добавлен staggered start RTSP-сессий (deterministic jitter по `cameraId` + приоритет), чтобы снизить burst при массовом запуске `GRID_9/16`.
- ✅ Параметры подавления вынесены в env-конфиг (см. блок "Тюнинг производительности").
- ✅ Добавлен manual checklist для перф-валидации: `docs/status/DESKTOP_LIVEVIEW_PERF_MANUAL_CHECKLIST.md`.

#### Подзадачи:

**4.3.3.1** Анализ производительности (4 часа)
- Профилирование CPU и памяти при 4/9/16 камерах
- Выявление узких мест (рендеринг, декодирование, сеть)
- Измерение FPS для каждой камеры
- Документирование метрик

**4.3.3.2** Оптимизация рендеринга (8 часов)
- Использование `remember` для кэширования компонентов
- Оптимизация перерисовок через `derivedStateOf`
- Ленивая инициализация VideoPlayer компонентов
- Использование `DisposableEffect` для правильной очистки

**4.3.3.3** Приоритизация потоков (8 часов)
- Реализация системы приоритетов (активная камера = высокий приоритет)
- Снижение качества для фоновых камер (автоматически)
- Приостановка невидимых потоков
- Возобновление при появлении в viewport

**4.3.3.4** Оптимизация памяти (6 часов)
- Ограничение буфера кадров (max 3 кадра на камеру)
- Автоматическая очистка старых кадров
- Оптимизация BufferedImage (переиспользование)
- Мониторинг использования памяти

**4.3.3.5** Оптимизация сети (6 часов)
- Пул RTSP соединений с переиспользованием
- Batch обработка кадров
- Адаптивный битрейт на основе производительности
- Обработка таймаутов и переподключений

#### Тюнинг производительности (env)

Параметры публикации render-метрик (Desktop):
- `IPCSS_METRICS_PUBLISH_MIN_INTERVAL_MS` — минимальный интервал публикации мелких render-only апдейтов.
- `IPCSS_METRICS_RENDER_FPS_DELTA` — порог изменения FPS для немедленной публикации.
- `IPCSS_METRICS_DROPPED_DELTA` — порог изменения dropped-frames для немедленной публикации.

Параметры staggered connect (Desktop RTSP):
- `IPCSS_RTSP_STAGGER_NORMAL_BASE_MS` — базовая задержка старта `NORMAL` потока.
- `IPCSS_RTSP_STAGGER_NORMAL_JITTER_MS` — jitter-окно для `NORMAL`.
- `IPCSS_RTSP_STAGGER_BACKGROUND_BASE_MS` — базовая задержка старта `BACKGROUND` потока.
- `IPCSS_RTSP_STAGGER_BACKGROUND_JITTER_MS` — jitter-окно для `BACKGROUND`.

Рекомендуемые профили:
- `GRID_9` (баланс): `MIN_INTERVAL_MS=1000`, `FPS_DELTA=2`, `DROPPED_DELTA=5`
- `GRID_16` (агрессивный anti-noise): `MIN_INTERVAL_MS=1500`, `FPS_DELTA=3`, `DROPPED_DELTA=8`

**Критерии приемки:**
- ✅ Стабильная работа с 16 камерами (30+ FPS на каждую)
- ✅ Использование памяти < 2GB для 16 камер
- ✅ CPU нагрузка < 80% на среднем ПК
- ✅ Плавное переключение между grid layouts

**Оценка времени:** 32 часа (4 дня)
