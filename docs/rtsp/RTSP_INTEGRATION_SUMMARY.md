## 🗓️ План реализации (MVP - 2-3 недели)

### Неделя 1: Базовая функциональность

**День 1-2: Подготовка окружения**
- Установить CMake, FFmpeg, pkg-config
- Проверить CMake конфигурацию
- **Результат:** Все зависимости установлены

**День 3-4: Компиляция библиотеки**
- Собрать `libvideo_processing` для Desktop
- Проверить экспорт символов
- **Результат:** Библиотека скомпилирована

**День 5: Генерация биндингов**
- Запустить `./gradlew :core:network:compileKotlinLinuxX64`
- Проверить сгенерированные файлы
- **Результат:** cinterop биндинги готовы

**День 6-7: Активация кода**
- Раскомментировать импорты в `NativeRtspClient.native.kt`
- Реализовать вызовы нативных функций
- Реализовать callback'и с StableRef
- **Результат:** Код компилируется

---

### Неделя 2: Тестирование и интеграция

**День 8-10: Базовое тестирование**
- Unit тесты для всех методов
- Интеграционные тесты с реальной камерой
- E2E тест с видеоплеером
- **Результат:** Базовая функциональность работает

**День 11-14: Интеграция с видеоплеером**
- Настроить HLS генерацию
- Проверить задержку (< 3 сек)
- Оптимизировать буферизацию
- **Результат:** Видео воспроизводится в веб-интерфейсе

**MVP готов!** ✅

### Неделя 3-4: Расширенная функциональность

**Аудио декодирование**

**Платформенная поддержка**
- Android (arm64-v8a, armeabi-v7a)

- Улучшение задержки (< 2 сек)

## 📋 Критерии готовности

### MVP (минимально жизнеспособный продукт)

- [x] RTSP клиент подключается к камере (Desktop)
- [x] Видео H.264 воспроизводится
- [x] Задержка < 3 секунд
- [x] Интеграция с видеоплеером работает
- [x] Базовые unit тесты пройдены

### Release (готовность к продакшену)

- [x] Поддержка H.265
- [x] Аудио декодирование (AAC, PCMU, PCMA)
- [x] Android поддержка (arm64-v8a)
- [x] iOS поддержка (arm64)
- [x] Задержка < 2 секунд
- [x] Покрытие тестами ≥ 60%
- [x] Автоматическое переподключение
- [x] Graceful degradation при ошибках

## 🚨 Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Несовместимость FFmpeg версий | Средняя | Высокое | Фиксированная версия в документации |
| Проблемы с NAT/Firewall | Высокая | Среднее | TCP транспорт как fallback |
| Различия между камерами | Высокая | Среднее | Тестирование с различными камерами |
| Высокая задержка на слабых устройствах | Средняя | Высокое | Оптимизация буферизации, аппаратное ускорение |
| Отсутствие реальных камер для тестирования | Средняя | Критическое | Использовать публичные RTSP серверы |

## 📚 Ресурсы

### Необходимое оборудование
-至少 3 IP-камеры (разные производители)
- Тестовый RTSP сервер
- Устройства для тестирования (Desktop, Android, iOS)

### Необходимое ПО
- FFmpeg 5.x или 6.x
- CMake 3.15+
- Xcode (для Apple платформ)
- Android Studio с NDK
- Visual Studio (для Windows)

### Команда
- 1 C++ разработчик (FFmpeg, RTP/RTSP)
- 1 Kotlin/Native разработчик
- 1 тестировщик
