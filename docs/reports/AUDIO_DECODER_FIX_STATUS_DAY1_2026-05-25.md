## 🚧 Обнаруженные проблемы

### Проблема 1: Дублирование определений аудио структур

**Описание:**
В `rtsp_client.cpp` уже содержатся определения `AACDecoder`, `G711Decoder`, `AudioResampler`, `DecodedAudioFrame` внутри секции `#ifdef ENABLE_FFMPEG`. При включении `#include "audio_decoder.h"` возникают конфликты компиляции.

**Временное решение:**
- Использовать встроенные в `rtsp_client.cpp` аудио декодеры
- `audio_decoder.cpp` используется как отдельный модуль для тестирования

**План решения:**
1. Убрать дублирующиеся определения из `rtsp_client.cpp`
2. Использовать функции из `audio_decoder.h/cpp`
3. Протестировать компиляцию

## 📝 Технические заметки

### Структура `DecodedAudioFrame`

**В `audio_decoder.h`:**
```c
struct DecodedAudioFrame {
    int16_t* samples;        // PCM samples (16-bit)
    size_t sampleCount;      // Количество samples
    int sampleRate;          // Частота дискретизации
    int channels;            // Количество каналов
    int64_t timestamp;       // RTP timestamp
};
```

**В `rtsp_client.cpp`:**
```cpp
struct DecodedAudioFrame {
    std::vector<int16_t> samples;  // PCM S16
    int sampleRate;
    int channels;
    int64_t timestamp;
    size_t sampleCount;
};
```

**Проблема:** Разные реализации (C-массив vs C++ vector)

**Решение:** Использовать C-интерфейс из `audio_decoder.h` для совместимости с FFI

### Поддерживаемые аудио форматы

| Кодек | RTP Payload Type | Sample Rate | Channels | Декодер |
|-------|------------------|-------------|----------|---------|
| AAC | 96 (обычно) | 44100, 48000 | 1-2 | `init_aac_decoder` |
| PCMU (μ-law) | 0 | 8000 | 1 | `init_g711_decoder(true)` |
| PCMA (A-law) | 8 | 8000 | 1 | `init_g711_decoder(false)` |
| MP3 | 14 | 44100, 48000 | 1-2 | Планируется |
