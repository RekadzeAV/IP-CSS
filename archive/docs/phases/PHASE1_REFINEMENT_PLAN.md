## 2. План доработки по шагам

### Блок A: Сервер — авто-подписка и конфиг (критично для MVP)

#### A.1. Конфиг ONVIF (задача 1.1.4)

**Цель:** Вынести настройки ONVIF в конфиг/переменные окружения.

**Файлы:**

- **Создать:** `server/api/src/main/kotlin/com/company/ipcamera/server/config/OnvifEventsConfig.kt`

  - Поля: `enabled: Boolean`, `subscriptionTimeSeconds: Int`, `pullIntervalMs: Long`, `pullTimeoutMs: Int`, `usePullPointByDefault: Boolean`
  - Чтение из env: `ONVIF_EVENTS_ENABLED` (default true), `ONVIF_SUBSCRIPTION_TIME_SEC` (3600), `ONVIF_PULL_INTERVAL_MS` (5000), `ONVIF_PULL_TIMEOUT_MS` (500), `ONVIF_USE_PULL_POINT` (true)
  - Функция `fromEnvironment(): OnvifEventsConfig`

- **Опционально:** пример конфига в `config/onvif-events.example.env` или дописать в `config/README-TEST-CAMERAS.md` раздел про ONVIF Events.

**Зависимости:** нет. Сделать первым, чтобы использовать в A.2 и A.3.

---

#### A.2. Подписка при старте API (задача 1.1.1 — старт)

**Цель:** При запуске сервера подписывать все подходящие камеры на ONVIF-события.

**Файлы:**

- **Изменить:** `server/api/src/main/kotlin/com/company/ipcamera/server/Application.kt`

  - После `cameraService.startMonitoring()`:
    - Инжектить `OnvifEventSubscriptionService` и (при необходимости) конфиг `OnvifEventsConfig`.
    - Если `OnvifEventsConfig.enabled == false` — ничего не делать.
    - Иначе в `CoroutineScope(Dispatchers.Default).launch`:
      - `cameraRepository.getCameras()`
      - Для каждой камеры: если подходит для ONVIF (URL http(s), есть учётные данные при необходимости) — вызвать `onvifEventSubscriptionService.subscribeToCameraEvents(camera.id, usePullPoint = config.usePullPointByDefault)`.
      - Ошибки логировать, не падать (одна камера не должна блокировать остальные).

- **Изменить:** `server/api/src/main/kotlin/com/company/ipcamera/server/service/OnvifEventSubscriptionService.kt`

  - Добавить опциональный параметр (или инжект) `OnvifEventsConfig`.
  - В `subscribeToCameraEvents` использовать из конфига: `subscriptionTime`, интервал/таймаут для PullPoint (если конфиг передан); иначе дефолты как сейчас.
  - Убедиться, что используется `camera.username` / `camera.password` (модель `Camera` в shared), либо привести к одному формату с `camera.credentials` при наличии маппинга на сервере.

**Критерий готовности:** После перезапуска API все камеры с http(s) URL подписываются на события (при включённом конфиге).

---

#### A.3. Подписка/отписка при изменении камер (задача 1.1.1 — add/update/delete)

**Цель:** При добавлении/обновлении камеры — подписаться или переподписаться; при удалении — отписаться.

**Файлы:**

- **Изменить:** `server/api/src/main/kotlin/com/company/ipcamera/server/routing/CameraRoutes.kt`

  - Инжектить `OnvifEventSubscriptionService` и `OnvifEventsConfig` (или только сервис, если конфиг внутри него).
  - **POST /cameras** (создание): после успешного `cameraRepository.addCamera(camera)` и отправки WebSocket:
    - Если конфиг ONVIF включён и камера подходит для ONVIF — `onvifEventSubscriptionService.subscribeToCameraEvents(createdCamera.id, ...)` в корутине, ошибки только логировать.
  - **PUT /cameras/{id}** (обновление): после успешного `cameraRepository.updateCamera(updatedCamera)`:
    - Если конфиг включён: вызвать `unsubscribeFromCameraEvents(id)`, затем при соответствии камеры ONVIF — `subscribeToCameraEvents(id, ...)`.
  - **DELETE /cameras/{id}**: после успешного `cameraRepository.removeCamera(id)`:
    - Вызвать `onvifEventSubscriptionService.unsubscribeFromCameraEvents(id)` (игнорировать ошибки или логировать).
  - **POST /cameras/bulk/delete**: для каждого успешно удалённого `id` — `unsubscribeFromCameraEvents(id)`.

**Вспомогательно:** Вынести проверку «камера подходит для ONVIF» в общую функцию (например, в `OnvifEventSubscriptionService` или утилиту): например, URL начинается с `http://` или `https://` и при необходимости наличие username.

**Критерий готовности:** Добавление/редактирование/удаление камеры через API приводит к корректной подписке/переподписке/отписке без падения сервера.

### Блок B: Клиенты — переподписка при восстановлении (задача 1.2.3)

**Цель:** При потере сети или недоступности камеры — не падать; при восстановлении — переподписаться.

**Файлы:**

- **Изменить:** `shared/src/commonMain/kotlin/com/company/ipcamera/shared/domain/service/CameraEventMonitoringService.kt`

  - В `initialize()` при `onFailure` от `startMonitoring` не только логировать, но и запоминать камеры с ошибкой (например, `Set<String>` cameraIds с failed).
  - Запустить фоновую периодическую задачу (например, раз в 30–60 секунд) или при возобновлении (если есть общий колбэк «приложение снова активно»): для камер из «failed» повторно вызывать `startMonitoring`; при успехе — убрать из «failed».
  - Ограничить частоту повторов (например, не чаще раза в 30 сек на камеру).

- **Опционально (Android):** в `MainActivity` или месте инициализации подписаться на `ConnectivityManager` / жизненный цикл и при возврате в foreground или появлении сети вызывать `eventMonitoringService.initialize()` или новый метод `retryFailedCameras()`.

**Критерий готовности:** После потери и восстановления сети мониторинг событий для ранее упавших камер возобновляется без перезапуска приложения (в пределах заданного интервала повтора).

#### D.2. Интеграционный тест (1.4.2)

**Цель:** Цепочка: мок ONVIF → подписка → создание события в сервисе → отправка в WebSocket.

**Файлы:**

- **Создать:** интеграционный тест (например, в `server/api/src/test` или в `core/network`), который:
  - Поднимает или использует мок ONVIF (например, заглушка HTTP, возвращающая валидный PullMessages ответ с одним событием),
  - Вызывает подписку на «камеру», затем имитирует получение события (или один запрос PullMessages),
  - Проверяет, что в `EventRepository` или через `EventService` появилось соответствующее событие,
  - При возможности проверяет, что по WebSocket было отправлено сообщение в канал событий (например, через тестовый WebSocket-клиент или запись вызовов `WebSocketManager.broadcastEvent`).

**Критерий готовности:** Один автоматический прогон цепочки подписка → событие → репозиторий (и при наличии — WebSocket) проходит.

## 4. Риски и примечания

- **Модель Camera:** в shared у `Camera` поля `username`/`password`; в `OnvifEventSubscriptionService` используется `camera.credentials?.username`. Нужно привести к одному варианту (например, везде использовать `camera.username`/`camera.password` или ввести обёртку/маппинг на сервере).
- **Проверка «подходит для ONVIF»:** на сервере лучше использовать ту же логику, что и в клиенте (URL http(s)); при необходимости позже добавить флаг из БД или из результата `testConnection` (capabilities.onvif).
- **Массовое удаление:** в `bulk/delete` вызывать `unsubscribeFromCameraEvents(id)` для каждого удалённого id после успешного `removeCamera`.

После выполнения этого плана Фаза 1 может считаться завершённой с точки зрения MVP (с оговоркой о ручной проверке на реальной камере).
