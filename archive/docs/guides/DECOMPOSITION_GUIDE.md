# 📋 Руководство по декомпозиции задач

**Версия:** 1.0  
**Дата:** 26 May 2026  
**Применяется:** Любыми AI-агентами, CI/CD, разработчиками  

---

## Когда применять

Задачу **необходимо** вынести в отдельный блок с полной декомпозицией при **любом** из критериев:

| # | Критерий | Описание |
|---|----------|----------|
| 1 | ⏱ >30 мин | Оценка непрерывной работы >30 минут |
| 2 | 🔗 Кросс-модульность | Затрагивает 3+ модуля (shared, server, web, native) |
| 3 | ❓ Неопределённость | Требования или API зависимостей неизвестны |
| 4 | 🖥 Внешняя среда | Требует настройки БД, сети, Docker, NAS |
| 5 | 🔄 Изменение архитектуры | Рефакторинг, миграция данных, переименование |
| 6 | 📦 >5 файлов | Изменяет более 5 файлов |
| 7 | 🆕 Новая фича | Реализация нового функционального блока |

---

## Формат вынесенной задачи

### 1. Заголовок

```markdown
# 🎯 [ТИП]: [Название]
# 📋 Задача: [ID или ссылка]
# ⏱ Оценка: [часы/дни]
```

**Типы:** `FEATURE`, `REFACTOR`, `BUGFIX`, `RESEARCH`, `INFRASTRUCTURE`, `DOCS`

### 2. Контекст

Почему задача выделена, предпосылки, ссылки на связанные документы/файлы/код.

### 3. Декомпозиция (Checklist)

Каждый пункт — законченная единица работы:

```
- [ ] [часы] [Название подзадачи]
  - Критерий: [Definition of Done для подзадачи]
  - Файлы: [список файлов]
  - Зависимости: [от каких подзадач зависит]
```

**Требования к подзадаче:**
- Чёткий критерий завершения
- Независимость от других пунктов
- Оценка в часах
- Не более 30 минут на реализацию

### 4. Таблица оценки

| Подзадача | Часы | Риски |
|-----------|------|-------|
| Подзадача 1 | Xч | Низкие/Средние/Высокие |
| Подзадача 2 | Xч | ... |
| **Итого** | **Xч** | |

### 5. Definition of Done

Чеклист критериев для всей задачи:

```markdown
- [ ] Критерий 1
- [ ] Критерий 2
- [ ] Все тесты проходят
```

## Пример

```markdown
# 🎯 FEATURE: HLS pipeline оптимизация для Desktop

## Контекст
Текущий HLS pipeline имеет задержку ~5-10 секунд. Требуется <2 секунд.
Связан: `RtspClient.kt`, `JvmRtspClient.kt`
Блокер для MVP Фазы 1 (1.1.4)

## Декомпозиция
- [ ] 2ч Исследовать текущий HLS pipeline
  - Критерий: документ с анализом latency
  - Файлы: `docs/research/HLS_LATENCY_ANALYSIS.md`
  
- [ ] 3ч Реализовать low-latency HLS сегментер (fMP4)
  - Критерий: сегменты с задержкой <1с
  - Файлы: `core/network/.../HlsSegmenter.kt`
  - Зависимости: от исследования

- [ ] 2ч Интегрировать оптимизированный HLS в Desktop плеер
  - Критерий: задержка видео <2с
  - Файлы: `platforms/client-desktop-x86_64/.../VideoPlayer.kt`

## Оценка
| Подзадача | Часы | Риски |
|-----------|------|-------|
| Исследование | 2ч | Низкие |
| HLS сегментер | 3ч | Средние |
| Интеграция | 2ч | Низкие |
| **Итого** | **7ч** | |

## Definition of Done
- [ ] Задержка Desktop видео <2 секунды
- [ ] Все тесты проходят
- [ ] Long-run тест 1 час без потери кадров
```
