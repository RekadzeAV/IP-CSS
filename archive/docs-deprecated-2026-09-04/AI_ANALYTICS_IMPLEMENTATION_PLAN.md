### Компоненты системы

1. **Нативный слой (C++)** - `native/analytics/`
   - Высокопроизводительная обработка видео
   - Интеграция с OpenCV, TensorFlow Lite
   - GPU ускорение (CUDA, OpenCL)

2. **Kotlin Multiplatform слой** - `shared/src/`
   - Кроссплатформенный API
   - Управление жизненным циклом
   - Интеграция с бизнес-логикой

3. **Серверный слой** - `server/api/`
   - REST API для управления
   - WebSocket для real-time событий
   - Хранение результатов

4. **UI слой** - `server/web/`
   - Визуализация результатов
   - Настройка зон детекции
   - Статистика и отчеты

## Фаза 1: Инфраструктура и базовые компоненты

**Приоритет:** 🔴 Критический  
**Оценка времени:** 2–3 недели (10–15 раб. дней)  
**Зависимости:** Нет

### Описание фазы

**Цели:** Подготовить окружение для нативных модулей аналитики: подключить OpenCV, TFLite, Tesseract, собрать утилиты для изображений и моделей, настроить JNI и логирование. Без этой фазы невозможна реализация детекторов.

**Входы:** Текущая структура `native/analytics/`, заголовки детекторов, скрипты сборки.  
**Выходы:** Собранная нативная библиотека с зависимостями, утилиты (ImageUtils, ModelManager, Logger), рабочие JNI-обертки, проходящие тесты инфраструктуры.

**Критерии приёмки:**
- Сборка `native/analytics` с OpenCV на Windows/Linux/macOS.
- Загрузка тестовой TFLite-модели из кода.
- Tesseract вызывается и возвращает текст (тестовая картинка).
- ImageUtils: конвертация RGB/BGR, ресайз, нормализация; unit-тесты зелёные.
- JNI: вызов нативного кода из JVM и получение результата без падений.

## Фаза 2: Детекция движения

**Приоритет:** 🔴 Высокий  
**Оценка времени:** 1–2 недели (5–10 раб. дней)  
**Зависимости:** Фаза 1 (задачи 1.1.*, 1.2.*, 1.3.*, 1.4.*)

### Описание фазы

**Цели:** Реализовать детекцию движения в нативном коде (Background Subtraction + морфология + зоны), подключить к Kotlin через JNI, интегрировать с потоком кадров и опционально с записью по движению.

**Входы:** Кадры в формате RGB/grayscale (буфер байт + width/height), опционально предыдущий кадр, список зон (полигоны/прямоугольники), порог чувствительности.  
**Выходы:** Флаг «движение есть/нет», уверенность, список зон с интенсивностью движения; при интеграции — события и управление записью.

**Критерии приёмки:**
- Нативный motion_detector возвращает результат по кадру + опционально предыдущему кадру.
- Поддержка зон: только движение внутри зон учитывается (или маска зон).
- AnalyticsServiceImpl.detectMotion() вызывает нативный код и возвращает MotionDetectionResult.
- Unit-тесты на статичном/движущемся кадре и на разных порогах зелёные.
- Опционально: FrameProcessor отдаёт кадры в motion-детектор; при движении создаётся событие/запись.
