# Определение MVP

**Дата:** 2026-03-01  
**Версия:** 1.0 (решения Фазы 0 зафиксированы 2026-03-01)  
**Статус:** Согласовано для реализации.

---

## Цель MVP

Минимально жизнеспособный продукт: приложение для просмотра и управления IP-камерами с поддержкой ONVIF, событий, базовой безопасности и при необходимости нативного RTSP.

---

## Обязательные фичи для MVP

- [x] **Камеры:** добавление, редактирование, удаление; просмотр списка и статуса.
- [x] **ONVIF Event:** подписка на события камер при старте сервера и клиентов; события отображаются в UI (список событий, уведомления).
- [x] **Видеопоток:** просмотр живого потока с камер (через RTSP или HTTP/MJPEG в зависимости от платформы).
- [x] **Безопасность (базовая):** certificate pinning для Desktop/Android клиентов из конфига; для web-клиента используется строгий HTTPS/TLS trust boundary (без browser pinning).
- [x] **Клиенты:** Desktop (JVM), Android; веб-клиент и сервер API — в scope MVP.

---

## Решения (Фаза 0, зафиксированы 2026-03-01)

### 1. «Нативный» RTSP — **Вариант A**

- **Принято:** В MVP достаточно RTSP через FFmpeg на Desktop/JVM; на Android — ExoPlayer (текущая реализация).
- **Не в scope MVP:** Обязательная доводка и полное тестирование FFmpeg-декодирования на всех платформах; нативный декодер на Android сверх ExoPlayer.
- **Итог:** Видеопоток в MVP — Desktop/JVM (FFmpeg при наличии), Android (ExoPlayer, при необходимости HLS fallback). Детали — `docs/ANDROID_RTSP_MVP.md`.

### 2. Принудительный HTTPS — **Включить в MVP**

- **Принято:** Редирект HTTP→HTTPS на сервере, опция «только HTTPS» в клиентах.
- **Обоснование:** Продукт может использоваться в недоверенных сетях; базовая безопасность включает и pinning, и принудительный HTTPS.
- **Документация:** `docs/HTTPS_AND_PINS_PRODUCTION_QUICKSTART.md`, `docs/PRODUCTION_SETUP_CERTIFICATE_PINNING_HTTPS.md`.

### 3. Миграции БД

- В MVP не блокируют релиз при условии: текущая схема стабильна, миграция 1→2 (и далее по версии) применяется корректно.
- Дальнейшее версионирование (миграции 2→3 и т.д.) — по мере изменения схемы, в рамках Фазы 5 плана. См. `docs/DATABASE_MIGRATIONS.md`.

## Критерии готовности MVP

1. Все пункты из «Обязательные фичи для MVP» реализованы и проверены.
2. По плану выполнены фазы 0, 1, 4; фазы 2 и 3 — в соответствии с выбранными решениями выше.
3. Есть краткая документация по развёртыванию и настройке (в т.ч. certificate pinning и HTTPS при необходимости).
4. Критичные сценарии покрыты тестами или сценариями ручной проверки.
