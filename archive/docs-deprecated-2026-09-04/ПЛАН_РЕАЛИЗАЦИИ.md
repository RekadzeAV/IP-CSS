## 3. Порядок выполнения и зависимости

```
Фаза 0 (подготовка)
    │
    ├──► Фаза 1 (ONVIF Event) ─── основной фокус
    │         │
    │         └──► Фаза 4 (кэш) может идти параллельно
    │
    ├──► Фаза 2 (безопасность) ─── параллельно с Фазой 1 или после
    │
    ├──► Фаза 3 (RTSP) ─── после стабилизации сборки; только при требовании нативного RTSP
    │
    └──► Фаза 5 (миграции БД) ─── в фоне, не блокер MVP
```

**Рекомендуемая последовательность до MVP:**

1. **Фаза 0** — согласовать MVP_DEFINITION, прогон тестов, ветки.
2. **Фаза 1** — убедиться, что всё работает; при необходимости провести и зафиксировать ручную проверку ONVIF (1.4.3).
3. **Фаза 4** — уже выполнена; при изменениях в репозитории — проверить кэши.
4. **Фаза 2** — уже выполнена; при деплое — проверить pinning и HTTPS по гайдам.
5. **Фаза 3** — выполнять 3.1.1 и доводки только если в MVP заложен нативный RTSP на Desktop/JVM.
6. **Фаза 5** — при изменении схемы БД добавлять миграции по описанному процессу.
