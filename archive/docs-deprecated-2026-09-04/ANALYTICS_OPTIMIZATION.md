# Оптимизация AI-аналитики (Фаза 8)

**Дата:** 1 March 2026

## Метрики пайплайна

- **GET** `/api/v1/cameras/{id}/analytics/metrics` — возвращает:
  - `processedFrames` — число обработанных кадров;
  - `skippedFrames` — число пропущенных кадров (при перегрузке).

Используйте эти метрики для мониторинга нагрузки и решения о снижении FPS аналитики или ограничении очереди.

## Рекомендации по профилированию

1. **Замер по этапам:** для каждого детектора (motion, object, face, ANPR) замерять время: препроцессинг, инференс, постобработка.
2. **Уменьшение копирований:** работа с `Mat`/указателями без лишних `clone`, переиспользование буферов в нативном коде.
3. **Ресайз:** детекция движения допустима в уменьшенном разрешении (полкадра или 1/4) для ускорения.
4. **Очередь кадров:** при переполнении обрабатывать только последний кадр (conflate) или ограничивать размер очереди.

## Устойчивость к перегрузке

- Пайплайн использует `Flow.sample(interval)` для ограничения частоты обработки.
- При необходимости добавьте ограничение размера очереди кадров и увеличение `skippedFrames` при пропуске.
- Кэш детекторов и моделей по `cameraId`/типу уже используется в `AnalyticsServiceImpl` (JVM/Desktop).

## Выбор моделей

- **Сервер:** полные модели (например, YOLOv8 640x640) для точности.
- **Мобильные:** лёгкие квантизованные модели (INT8) и уменьшенный вход (416 или 320) по конфигу.
