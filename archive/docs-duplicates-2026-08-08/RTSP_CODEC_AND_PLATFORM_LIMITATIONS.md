# Ограничения RTSP: кодеки, профили и зависимость от FFmpeg

**Связанные документы:** [RTSP_CLIENT.md](RTSP_CLIENT.md), [DEPENDENCIES.md](DEPENDENCIES.md), [MVP_PHASED_IMPLEMENTATION_PLAN.md](MVP_PHASED_IMPLEMENTATION_PLAN.md) (Фаза 3).

## Обзор

В проекте RTSP-поток обрабатывается в два этапа: **протокол RTSP** (получение RTP/кадров) и **декодирование видео**. Поддерживаемые кодеки и необходимость FFmpeg на устройстве зависят от платформы.

---

## Поддерживаемые кодеки и профили

### Видео

| Кодек        | Алиасы в конфиге      | Декодирование (JVM/Desktop) | Профили (тестированы) |
|-------------|------------------------|-----------------------------|------------------------|
| **H.264/AVC** | H.264, H264, AVC       | ✅ FFmpeg (avcodec)         | Baseline, Main, High   |
| **H.265/HEVC** | H.265, H265, HEVC      | ✅ FFmpeg (avcodec)         | Main, Main 10 (зависит от сборки FFmpeg) |
| **MJPEG**   | MJPEG, JPEG            | ✅ ImageIO (без FFmpeg)     | —                      |
| Другие      | —                      | ❌ Не поддерживаются       | —                      |

Определение кодека из строки: `String.toVideoCodec()` в `core/network/.../VideoDecoder.kt`.

### Аудио

- RTSP-клиент может **получать** аудиопотоки (RTP), но в текущей реализации **декодирование аудио** (например AAC) в общем пайплайне не реализовано.
- Для воспроизведения «звука с камеры» в MVP обычно используется сценарий RTSP → HLS на сервере или плеер с собственной поддержкой аудио (например ExoPlayer на Android).

## Нужен ли FFmpeg на устройстве?

Зависит от платформы и от того, используется ли **нативное декодирование** в клиенте или поток отдаётся внешнему плееру/HLS.

### JVM / Desktop (Kotlin JVM)

| Вопрос | Ответ |
|--------|--------|
| Нужен ли системный FFmpeg на машине? | **Нет.** Используется **ffmpeg-platform** (JavaCPP) — FFmpeg поставляется в составе зависимостей (например `org.bytedeco:ffmpeg-platform:8.0.1-1.5.13`). |
| Где используется? | `VideoDecoderImpl` (H.264/H.265), только для целевого набора JVM/Desktop. |
| MJPEG | Декодируется через `ImageIO`, FFmpeg не используется. |

Отдельная установка FFmpeg на ПК/сервере для **клиентского** просмотра через этот декодер **не требуется**.

### Android

| Вопрос | Ответ |
|--------|--------|
| Нужен ли FFmpeg на устройстве? | **Не обязательно.** Варианты: (1) нативная библиотека `video_processing` с FFmpeg внутри (если собрана с ENABLE_FFMPEG) — тогда FFmpeg встроен в APK; (2) воспроизведение через **ExoPlayer** или другой плеер — тогда декодирование идёт через MediaCodec/системные кодеки, FFmpeg на устройстве не нужен. |
| Текущая реализация | `NativeRtspClient` (JNI к C++ RTSP-клиенту). Декодирование может быть доведено до ExoPlayer или оставлено в нативной библиотеке — см. этап 3.2 в MVP плане. |
| Рекомендация для MVP | Если не требуется «нативный» декодер в приложении — предпочтительно использовать ExoPlayer для RTSP; тогда зависимость от FFmpeg на устройстве отсутствует. |

### iOS / Kotlin Native (Desktop native)

| Вопрос | Ответ |
|--------|--------|
| Нужен ли FFmpeg на устройстве? | Зависит от сборки нативной библиотеки. При сборке `video_processing` с **ENABLE_FFMPEG=ON** FFmpeg включается в саму библиотеку; отдельная установка на устройстве не нужна. |
| Текущий статус | `VideoDecoder` для native — заглушка/неактивированный код (cinterop, раскомментирование после сборки). Декодирование через нативную библиотеку пока не задействовано в продакшене. |

### Сборка нативной библиотеки (C++)

Для **сборки** нативной библиотеки RTSP/декодера (не для конечного пользователя):

- **FFmpeg** (libavformat, libavcodec, libavutil, libswscale, libswresample) нужен в среде сборки (см. [DEPENDENCIES.md](DEPENDENCIES.md)).
- Windows: сборка с [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) или указание путей в CMake.
- Linux: `sudo apt install libavformat-dev libavcodec-dev ...`
- macOS: `brew install ffmpeg`

Это касается только разработки и сборки, не работы приложения на JVM/Desktop с ffmpeg-platform.

## Краткая сводка для разработки

- **Кодеки:** H.264, H.265, MJPEG (видео). Профили H.264: Baseline, Main, High.
- **JVM/Desktop:** FFmpeg **не** нужен на устройстве — используется ffmpeg-platform в JAR.
- **Android:** FFmpeg на устройстве **не** обязателен при использовании ExoPlayer; при использовании нативной библиотеки с FFmpeg — он встроен в приложение.
- **Сборка нативных библиотек:** FFmpeg нужен только в среде сборки (см. DEPENDENCIES.md).

При появлении новых платформ или вариантов воспроизведения документ следует обновить (кодеки, профили, зависимость от FFmpeg по платформам).
