# План тестирования VideoDecoder

## Обзор

Этот документ описывает план тестирования нативного и JVM декодера видео для Desktop приложения.

## Цели тестирования

1. Проверка корректности декодирования H.264/H.265 потоков
2. Проверка производительности декодирования
3. Проверка обработки ошибок и восстановления
4. Проверка работы с различными разрешениями и битрейтами
5. Проверка стабильности при длительной работе

## Тестовые сценарии

### 1. Базовое декодирование

#### 1.1 H.264 поток
- **Цель**: Проверить декодирование H.264 потока
- **Шаги**:
  1. Подключиться к камере с H.264 кодеком
  2. Запустить воспроизведение
  3. Проверить, что кадры декодируются корректно
  4. Проверить, что разрешение определяется правильно
- **Ожидаемый результат**: Видео воспроизводится без артефактов, разрешение корректное
- **Критерии успеха**:
  - FPS >= 25 для 1080p
  - Задержка декодирования < 40ms
  - Нет визуальных артефактов

#### 1.2 H.265 поток
- **Цель**: Проверить декодирование H.265 потока
- **Шаги**: Аналогично H.264
- **Ожидаемый результат**: Видео воспроизводится корректно
- **Критерии успеха**: Аналогично H.264

#### 1.3 MJPEG поток
- **Цель**: Проверить fallback на MJPEG
- **Шаги**: Подключиться к камере с MJPEG кодеком
- **Ожидаемый результат**: Видео воспроизводится через ImageIO

### 2. Динамическое изменение разрешения

#### 2.1 Изменение разрешения во время потока
- **Цель**: Проверить обработку изменения разрешения
- **Шаги**:
  1. Подключиться к камере
  2. Изменить разрешение на камере во время воспроизведения
  3. Проверить, что декодер адаптируется
- **Ожидаемый результат**: Декодер переинициализируется и продолжает работу
- **Критерии успеха**:
  - Переинициализация происходит автоматически
  - Нет падений или зависаний
  - Новое разрешение отображается корректно

### 3. Обработка ошибок

#### 3.1 Потеря пакетов
- **Цель**: Проверить устойчивость к потере пакетов
- **Шаги**:
  1. Подключиться к камере
  2. Имитировать потерю пакетов (отключить сеть на 1-2 секунды)
  3. Проверить восстановление
- **Ожидаемый результат**: Декодер восстанавливается после потери пакетов
- **Критерии успеха**:
  - Восстановление происходит автоматически
  - Нет падений приложения

#### 3.2 Поврежденные данные
- **Цель**: Проверить обработку поврежденных данных
- **Шаги**: Отправить поврежденные NAL units
- **Ожидаемый результат**: Декодер пропускает поврежденные кадры и продолжает работу

#### 3.3 Отсутствие SPS/PPS
- **Цель**: Проверить обработку отсутствия параметров кодека
- **Шаги**: Подключиться к потоку без SPS/PPS в начале
- **Ожидаемый результат**: Декодер ждет SPS/PPS или использует fallback

### 4. Производительность

#### 4.1 Метрики производительности
- **Цель**: Измерить производительность декодирования
- **Метрики для измерения**:
  - Среднее время декодирования кадра (мс)
  - FPS (кадров в секунду)
  - Использование CPU (%)
  - Использование памяти (MB)
  - Задержка (latency) от получения кадра до отображения
- **Целевые значения**:
  - 1080p (1920x1080): < 40ms на кадр, >= 25 FPS
  - 720p (1280x720): < 20ms на кадр, >= 30 FPS
  - 480p (640x480): < 10ms на кадр, >= 30 FPS
  - CPU usage: < 50% для одного потока
  - Memory: < 200MB для декодера

#### 4.2 Нагрузочное тестирование
- **Цель**: Проверить работу при длительной нагрузке
- **Шаги**:
  1. Запустить воспроизведение на 1 час
  2. Мониторить метрики производительности
  3. Проверить утечки памяти
- **Ожидаемый результат**: Стабильная работа без деградации производительности
- **Критерии успеха**:
  - Нет утечек памяти
  - Производительность стабильна
  - Нет падений

### 5. Различные разрешения и битрейты

#### 5.1 Тестирование различных разрешений
- **Разрешения для тестирования**:
  - 640x480 (VGA)
  - 1280x720 (HD)
  - 1920x1080 (Full HD)
  - 2560x1440 (2K) - если поддерживается
  - 3840x2160 (4K) - если поддерживается
- **Ожидаемый результат**: Все разрешения декодируются корректно

#### 5.2 Тестирование различных битрейтов
- **Битрейты для тестирования**:
  - Низкий (1-2 Mbps)
  - Средний (4-6 Mbps)
  - Высокий (8-12 Mbps)
- **Ожидаемый результат**: Декодер работает стабильно при всех битрейтах

### 6. Множественные потоки

#### 6.1 Одновременное декодирование нескольких потоков
- **Цель**: Проверить работу с несколькими камерами одновременно
- **Шаги**:
  1. Подключиться к 2-4 камерам одновременно
  2. Запустить воспроизведение всех потоков
  3. Мониторить производительность
- **Ожидаемый результат**: Все потоки декодируются корректно
- **Критерии успеха**:
  - Каждый поток работает стабильно
  - Общее использование CPU < 80%
  - Нет конфликтов ресурсов

## Инструменты для тестирования

### 1. Логирование
- Использовать `mu.KotlinLogging` для логирования
- Включить метрики производительности в логи
- Логировать ошибки декодирования

### 2. Мониторинг производительности
- Использовать JVM профилировщики (JProfiler, VisualVM)
- Мониторить использование CPU и памяти
- Отслеживать метрики декодирования из логов

### 3. Тестовые камеры
- Реальные IP-камеры с различными кодеками
- Тестовые RTSP потоки (если доступны)
- Симуляторы RTSP потоков
